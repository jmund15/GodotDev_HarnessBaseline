# The Design Contract — invariants for autonomous architecture work

> Single source of truth for WHAT must hold when an agent runs a design process autonomously. [`/design_drive`](../../commands/design_drive.md) is the consumer; future autonomous design surfaces reference this file rather than restating it. Not a skill — no frontmatter, not directly invocable.
>
> **Scope split — verification, not cognition.** This file prescribes artifacts and gates (what must be true at design-lock). It deliberately does NOT prescribe process (what to read, what agents to spawn, exploration order or depth) — that is the orchestrator's judgment per the `orchestration` skill. Every clause here exists because the agent *can't know* project facts, *doesn't own* taste, or is *structurally biased* about its own designs — never because it can't structure its own thinking. Apply that litmus before adding a clause.

## Clauses

The design-lock report (clause 8) states, per clause, how it was satisfied — or what couldn't be.

1. **Grounding** — every design decision cites its source: the house design doctrine (`architecture_philosophy`, plus `jmodot` / `pp_subsystems` when the topic touches them), `game_vision`, an existing design doc, the roadmap, auto-memory, the codebase inventory, or a user-stated prior. A question no source answers is, by definition, a taste-fork (clause 2). *Litmus: "can I cite where this answer comes from?" No → taste-fork, never a guess.*
   - **Documentation is a claim to CHECK, never a source to CITE.** A codebase citation means the declaration and its call sites — `Grep`/LSP output over code. An XML `<summary>`, a `///` comment, or a memory note's aspirational line is not evidence: this repo's doc comments name deleted types, describe capabilities the implementation discards, state hypotheticals as shipped incidents, and promise members that were never written. They read as authoritative and are the one source nothing validates. A type existing does not make a seam live — check readers, not just the declaration. *Litmus: "did I read the code, or something written about the code?"*
   - **The doctrine is LOADED before drafting, never consulted after.** Skills have no auto-load mechanism — only `.claude/rules/*.md` auto-load, via `paths:` frontmatter. An unloaded skill is an uncited source, and auto-memory returning topic gotchas masks the gap because those echo doctrine fragments. `rules/design_litmus.md` is the always-on *pointer* to the doctrine ("Full doctrine: `architecture_philosophy` skill"), not a substitute for it: it carries the seven introduction litmi, not the pattern catalogue, the component-contract phases, or the three-way capability/polymorphism/dispatch choice.
2. **Taste is never decided** — [`appetite_invariant.md`](appetite_invariant.md) governs classification. Taste-forks accumulate into a batch for design-lock; a taste-fork the design cannot proceed past is a halt, not a judgment call. N batched taste-forks at design-lock is a SUCCESS state.
   - **The batch persists as it accumulates.** Each fork is appended to the topic folder's `decisions.md` `## Frontier` in the turn it is classified, per [`common.md §8`](common.md) — never held in session context until design-lock. That append is what makes an autonomous drive resumable mid-flight; without it a dead session loses the entire frontier. Out-of-scope calls and fog entries follow the same rule.
3. **Independent adversarial review** — before design-lock, the drafted design passes ≥1 adversarial pass by FRESH independently-dispatched agents ([`/architecture_brainstorm_redteam`](../../commands/architecture_brainstorm_redteam.md) Mode A `--auto`, or an equivalent independent panel). Composition follows the redteam's Step 0.5 doctrine — fixed floor + conditional + risk-derived bespoke lenses, each bespoke mandate naming its hunted failure mode; timing is free. Independence is not — self-review by the designing context never substitutes (`feedback_delegate_output_trust`).
   - **Citations resolve BEFORE dispatch.** Run `python .claude/tools/verify_doc_citations.py <doc> --repo <root>` and clear every unresolved symbol/path first (a retraction table naming absent symbols is the sanctioned exception — the tool's docstring says so). A panel spent re-checking citations is a panel not spent on the argument: the mechanical check costs seconds, the panel costs hundreds of thousands of subagent tokens. It is a floor, not a substitute — it proves a symbol exists, never that a claim about it is true.
4. **Abstraction inventory** — existing 2+ subclass families in the touched domains are inventoried (semantic-search → LSP `findReferences`) before any new type is committed (`feedback_inspect_existing_abstractions_first`). Extending beats inventing parallels.
5. **Artifact contracts** — the outputs are the same artifacts the human-in-the-loop flow produces, through the same gates. These are artifact-quality gates, not cognition scaffolding — they bind even when the process is free-form:
   - Design doc per [`common.md §5`](common.md) conventions (folder-per-topic, frontmatter, status taxonomy) plus [`architecture_brainstorm`](../architecture_brainstorm/SKILL.md) Step 6's structure expectations, including the opening At-a-glance section.
   - Parts authored against [`architecture_brainstorm`](../architecture_brainstorm/SKILL.md) Step 5's full sub-procedure chain (readiness gate, consolidation + cohesion litmi, seam-ownership, API + Test Pin).
   - Doc self-review per `architecture_brainstorm` Step 7's checklist (placeholder / contradiction / no-orphans / seam-ownership / readiness-gate audits).
   - `roadmap.md` only via `/update_roadmap` — the single-executor rule holds at every depth.
6. **Decision ledger** — every autonomously-resolved decision lands in the topic folder's `decisions.md` `## Decided` ([`common.md §8`](common.md)) as `<decision> — <source cited per clause 1> — <one-line rationale>`, appended when it is resolved. The design doc's `## Decision Ledger` section is a LINK to that file, never a second copy of the entries. Post-hoc auditability is what substitutes for per-decision pre-approval; an unlogged decision is an unauthorized one.
7. **Hard gate** — no implementation (code, scenes, scaffolds) before design-lock approval. Inherits `architecture_brainstorm`'s Hard Gate verbatim. **Self-test — a design session produces decisions, not deliverables:** count the entries this session banked in `## Decided`, `## Frontier`, and `## Out of scope`. Prose written is not the measure; a session that produced a long doc and no banked decisions did not design.
   - **Prototype carve-out (narrow).** A fork the design classifies as *feel-unknowable-by-discussion* — its answer turns on how something reads or responds at runtime — may exit as a `prototype-pending` Part without counting as an unresolved fork at design-lock, PROVIDED `prototypes/<slug>/QUESTION.md` states both the question and the shape of its answer (`prototype` skill). Bank it in `decisions.md` `## Blocked` naming the prototype as the unblocker. Throwaway code on the never-merged `prototype/<slug>` branch is not implementation of this design, so the gate holds. A generic "we'll figure it out later", or a fork whose answer shape cannot be stated, is refused exactly as before.
8. **Design-lock** — ONE mandatory human checkpoint, before `/update_roadmap` and before any implementation chaining. Present: (a) design summary, (b) the batched `## Frontier` as a frontier round ([`common.md §9`](common.md)) — genuinely preference-dependent → multiple live options; clear winner → recommended solution + approve/feedback, (c) the decision ledger, (d) the per-clause compliance report. **Blast-radius litmus** sets presentation depth: greenfield system / new top-level concept / framework ↔ project boundary / 2+ subclass family refactor / deletion or replacement of an existing system → offer a full section-level walkthrough; below it → summary + ledger suffice. The gate itself is never skipped, whatever the depth.

## Failure modes each clause exists for

| Without | What ships |
|---|---|
| 1–2 | The agent invents the user's vision — appetite decided silently; downstream Parts inherit it as if chosen |
| 3 | Plausible self-agreeing designs — the designing context can't see its own blind spots, regardless of model tier |
| 4–5 | A well-thought design badly integrated: parallel abstractions, orphaned claims, hand-edited roadmaps |
| 6, 8 | No audit surface — auto-resolving obvious decisions is the whole point, but without the ledger you can't verify they were obvious |
