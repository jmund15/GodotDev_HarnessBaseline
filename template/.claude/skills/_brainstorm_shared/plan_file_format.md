# Plan-file format (shared)

What a plan file must read like: the artifact [`/plan`](../../commands/plan.md) writes, [`/review`](../../commands/review.md) plan mode reviews, the owner approves and [`/drive`](../../commands/drive.md) executes.

A plan file is a **context-free execution document** for a cold reader (the executor, and the owner reviewing it for approval) who wants the final realized procedure, not the discovery history.

- **Resolved design as fact.** Never "the design said X, we changed to Y": write Y. A prototype-settled answer is one of these facts: pin it under `Constraints` citing `prototypes/<slug>/ANSWER.md`, never restate it as a question the executor re-decides.
- **Constraints cite their evidence, never copy it.** The `Constraints` section names the `/explore` dossier path, then lists each constraint as its dossier claim id plus a one-line statement. The reviewer reads the quotes from the dossier, so copying them only lengthens what every reader re-reads. A constraint no dossier holds, such as an owner ruling or a hand memory search, carries its own evidence quote.
- **Plan size follows the work.** Every reviewer and the executor read the whole plan, so it carries what they need to act and cites evidence by dossier id. Keep cohesive slices in one plan while the complete plan fits its reviewers and executor. A plan that cannot be planned and reviewed whole is size parts (`/plan` step 2): split it by behaviour.
- **Milestones.** A plan at size milestones groups its slices into milestones, each ending at a verifiable state the drive reports.
- **Load-bearing facts carry their verification.** A fact the plan depends on is verified in the plan, or assigned to a named spike or test. A count of repo entities (files touched, implementers, call sites, inheritors, scene nodes) carries the method that produced it (`LSP findReferences`, an inheritor sweep, an explicit glob), or is written `unknown — not enumerated`. **`unknown` is a legal record, never a legal bound:** a plan may not claim a bounded file list on a count written `unknown`, so a plan that needs the bound enumerates first.
- **Rationale woven inline** at the decision it justifies: one concise clause where a choice is non-obvious or dodges a named gotcha, in the relevant section or slice. Never a trailing "Decision record" or a leading "Scope resolution" preamble.
- **Decision promotion is gated; recording is not.** Record rationale inline liberally. Carrying a decision past the plan (into the design doc or a memory rule at plan completion) requires all three: **hard to reverse**, **surprising without context**, **the result of a real trade-off**. Miss one and it dies with the plan.
- **Focus deviation is marked in the header, verbatim.** A plan whose work `Claude/Meta/Development-Focus.md` pauses, or that pulls scope forward against it, opens its header block with a line starting `**Focus note (advisory):**`, naming what the focus pauses, the force that overrides it, and that it is advisory rather than blocking. Use that literal string when recording the deviation under `Development-Focus.md` → `## Focus deviations`. Not deviating: no line.
- **No process-meta sections.** The drift, critique and convergence narrative belongs in the approval message (`/plan` step 6), not the plan.
- **No open owner decisions at approval.** Presenting the plan asserts it is ready; an unresolved fork means it is not. Resolve every fork needing the owner before presenting, as one batched packet, and write the picks in as fact. Under explicit unattended authority, a reversible analytical fork with a recommendation is decided provisionally and recorded in the plan instead of blocking. A taste fork (`appetite_invariant.md`) stays the owner's even when reversible. Executor latitude (a detail the executor settles at code time) may be stated as latitude; that is not an open question.
- **Pre-agreed seams, caller first.** The plan names the contract each slice hands the next (signature, owning type, call direction) before slice 1 starts, and writes the consuming call site as it will read before the signature that serves it. A seam whose caller was never written is a signature guess. The contract itself is `design_litmus` #7. An executor that must decide a seam mid-slice is reading a defective plan: it reports the gap rather than inventing one.
- **Slice shape.** The shape rules (green alone, a tracer first slice, expand–contract for a wide refactor) are `/drive` §Slice rules; the plan records which shape it uses. Every slice carries a one-line **test intent**: the named failing test that gates it (the test-first domain), the integration assertion, the row of the project's agent playtest command that walks a person's task on the rendered build, or an explicit `subjective — <who judges>` (a playtest, the owner, a review seat), which covers taste only (`appetite_invariant.md` *Usability is analytical*).
- **A test intent fails until the slice's unknown is resolved correctly.** Put the scoring step, a hand-labelled sample, in the plan before the slice that tunes against it, or split the slice out as a `subjective` job.
- **Root acceptance.** A plan serving an owner's goal maps each requirement and exclusion in the state file's `## Goal` and `## Owner decisions` to a row: slice → test intent → rendered scenario → the judgment only the owner makes, or `none`. A rendered scenario is the real scene with its real sensors, collisions and default settings, and what a kept run log or capture of it must show, across each state the behaviour crosses (a target still, moving, lost and reacquired). A row for a derived value asserts the value in each situation (`architecture_philosophy` §Behaviour per situation). Parallel plans serving one goal share its state file, and each requirement needs a row in one of them; a plan names the sibling plan that maps each requirement it does not, and `/drive` §Close verifies their union. For a task a person does on a rendered screen, the rendered scenario is the agent playtest command's walk of that task, and the Person surface lists the tasks.
- **Self-checked before hand-off.** The plan settles what its drafter's own reads settle. Run `tools/verify_doc_citations.py --kinds path,command --only missing` over the plan and fix each miss. For every replaced or renamed surface, `git grep` its consumers and read the callers. Confirm each unknown left open needs an execution result to settle; a test's fixture values, a behaviour's boundary values and the inputs a seam's stated behaviour reads are unknowns too. Review then spends its seat on design, not on facts the drafter could read.
- **Job map (required section, `## Job map`).** One row per slice: its write set, the slices it waits on, and its route, either a job or `inline` with the reason it stays with the session (`orchestration`). A one-slice plan writes one row. A job row also names its tier, its work class (ambiguous or clearly defined) and its bar (cost, or quality where cheaper models fail the work), never a model: a model named at plan time fixes the provider before launch-time capacity is known (`orchestration`'s model table picks it at launch). An ambiguous row names its unknown, how execution settles it (a probe, experiment or test), and the bounds of the executor's choice. A finding outside those bounds is a halt. A file list is never such a bound, because the write set is a forecast. `/drive` starts from this map.
- **Out of scope (required section).** One-line entries naming what this plan deliberately does not do, including anything the design parked. `None` is a valid body; absence lets every reviewer re-litigate the boundary.
- **One shape per plan file.** Partition separable code and meta work into one plan per shape. Harness edits made in service of a production change (a domain row added because a new subsystem landed) are not a second shape: they have no deliverable apart from that plan. Within a shape, split only when items stop sharing a plan's spine, or a reviewer or executor cannot read the complete plan. The cohesion litmus: one `Constraints` block and one `Verification` section genuinely cover them all. Let cohesion and fit decide, never item count.
- **Three architecture-bearing sections** (required on a plan that touches production code; only the architecture thinking can fill them, and the reviewer flags an absent one as critical):
  - **Families:** every family extended or introduced, with a one-line axis statement per new rung or variant ("this rung varies X; the base varies Y"). Non-nesting axes state why the design is not a composed strategy (`architecture_philosophy` §Orthogonal axis).
  - **Authored surfaces:** every new authored field, scene node, data key or resource field, each with its single home, its named consumer, and its misconfiguration failure mode with the loud mechanism (a configuration warning, a throw at init, a lint).
  - **Person surface:** what the person who uses this change sees and does once it lands. For an author in the project's editor: what the inspector and scene tree show, what is hand-configured, what is automatic, what validates it. For an end user: each task the change adds or alters, as who + situation + goal, step by step, in each view it crosses and each situation the person meets it in (`architecture_philosophy` §Behaviour per situation), with what confirms it worked, at each data size the project's UI skill names. Each step names the approved mock-up frame it follows, or `no mock-up` and the design rule the project's UI skill applies. A Root acceptance row walks each task.
  - `None — <reason>` is a valid section body (a pure retirement); an absent section is not.
- **Two harness-bearing sections** (required instead on a meta plan, one that writes only `.claude/**` or docs; the three above have no referent on markdown):
  - **Surfaces touched:** every harness artifact edited, each marked always-loaded or on-demand, with the citations pointing at it (renames, moved sections and renumbered `§N` are what rot), and for each renamed, rewritten or deleted surface the `git grep` that finds its callers.
  - **Verification:** per artifact, the named check that proves the edit works: the hook fires on a crafted input, the script runs its success and failure paths, the renamed key has no stale reference, the cited path resolves, the JSON still parses. "Reviewed the diff" is not a check.
- **A short plan keeps its shape's required sections as one line each.** A plan that skips plan review (small, local, reversible work, `/plan` step 5) writes each of the three architecture sections, or a meta plan's two harness sections, as `Not applicable — design settled (<the fact that settled it>)`. The section is still present, so the absence rule stands.
- **Closing steps (Definition of Done):** `/drive` §Close owns the close sequence.
