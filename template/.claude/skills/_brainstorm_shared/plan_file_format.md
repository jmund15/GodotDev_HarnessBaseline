# Plan-file format (shared)

What a plan file must read like — the artifact presented for the user's approval and that [`/plan_handoff`](../../commands/plan_handoff.md) / [`/part_execute`](../../commands/part_execute.md) execute. Referenced by [`/part_drive`](../../commands/part_drive.md), those two, and CLAUDE.md.

A plan file is a **context-free execution document** — for a cold reader (the executor, AND the user reviewing it for approval) who wants the final realized procedure, not the discovery history. Optimizing it serves both.

- **Resolved design as fact.** Never "the design said X, we changed to Y" — write Y. A prototype-settled answer is one of these facts: pin it under `Constraints` citing `prototypes/<slug>/ANSWER.md`, never restate it as a question the executor re-decides.
- **Counted cardinalities.** A count of repo entities — files touched, implementers, call sites, inheritors, scene nodes — carries the method that produced it (`LSP findReferences`, an inheritor sweep, an explicit glob), or is written `unknown — not enumerated`. An estimate offered as the basis for a go/no-go decision is the failure this prevents; measured instances under-counted by 2.5×, 6×, and ~150 sites. **`unknown` is a legal record, never a legal bound** — a plan may not claim a bounded file list on a count written `unknown`, and [`/part_drive`](../../commands/part_drive.md) valve (b) halts on an unbounded list, so a plan that needs the bound enumerates first.
- **Rationale woven inline** at the decision it justifies (one concise clause where a choice is non-obvious or dodges a named gotcha), in the relevant section/slice — never a trailing "Decision record" dump or a leading "Scope resolution" preamble.
- **Decision promotion is gated; recording is not.** Record rationale inline liberally — it costs one clause. Carrying a decision PAST the plan (promoted at plan completion to the design doc or a memory rule) requires all three: **hard to reverse**, **surprising without context**, **the result of a real trade-off**. Miss one and it dies with the plan — an easy reversal just gets reversed, an unsurprising choice raises no questions, and a decision with no real alternative records nothing but "we did the obvious thing".
- **Focus deviation is marked in the header, verbatim.** A plan whose work is paused by `Claude/Meta/Development-Focus.md` — or that pulls scope forward against it — opens its header block with a line starting `**Focus note (advisory):**`, naming what the focus pauses, the force that overrides it, and that it is advisory rather than blocking. That literal string is the collection key for the ledger at `Development-Focus.md` → `## Focus deviations`, so a deviation phrased any other way is invisible to review. Not deviating → no line. Exemplar: `.claude/plans/proto-sand-procgen-demo-floor.md:6`.
- **No process-meta sections.** No "plan_part drift", "critique trail", "convergence basis", "round N". That narrative belongs in the approval-presentation message, not the plan.
- **No open user-decisions at approval.** Presenting the plan asserts it is ready; an unresolved fork means it isn't. Resolve any fork needing the user's input via `AskUserQuestion` (batch all forks into one call — max 4, chain if more) BEFORE presenting, and write the picks in as fact. Executor-latitude (an implementation detail the executor settles at code-time) may be stated as latitude — that is not an open question.
- **Pre-agreed seams.** The plan names the contract each slice hands the next — signature, owning type, call direction — before slice 1 starts. An executor that must decide a seam mid-slice is reading a defective plan: it reports the gap rather than inventing one.
- **Slice shape.** Slice 1 of a multi-slice plan is a thin end-to-end tracer touching every layer the feature crosses, proving the seams — not a complete first layer. Wide mechanical refactors (blast radius too large for any vertical slice to land green) instead run expand–contract: add the new path, migrate callers in batches, delete the old path — separately-green steps, one gate run each. Every slice carries a one-line **test intent**: the named failing test that gates it (Logic domain), the ISceneRunner assertion (Gameplay), or an explicit "subjective — manual playtest".
- **Out of scope (REQUIRED section).** One-line entries naming what this plan deliberately does not do, including anything the design parked. `None` is a valid body; absence lets every reviewer re-litigate the boundary.
- **One shape per plan file.** A plan covers exactly one `PLAN_SHAPE` (`/plan_check` Phase 1a owns that term) — the required sections below branch on it, and a mixed plan classifies `code`, so the two lenses that would judge its `.claude/**` edits never run and those edits get no other gate (meta commits are gate-exempt; there is no compiler and no test). Work spanning both shapes partitions into one plan per shape, each `/plan_check`ed on the lens set its own shape selects. Harness edits made *in service of* a production change (a domain row added because a new subsystem landed) are not a second shape: they have no deliverable apart from that plan.
  **Shape is the only hard partition; granularity within a shape is a cohesion call.** Default to one plan per shape and split further only when the items stop sharing a plan's spine — the litmus is whether one `Constraints` block and one `Verification` section genuinely cover them all. Two mechanical chores share a plan; two dense items that would each need their own constraints, their own seams, and their own verification are two plans already, and filing them as one degrades the exact sections `/plan_check` reads hardest. Splitting costs an extra gate run, so let cohesion decide it — never item count.
- **Three architecture-bearing sections (REQUIRED on a plan that touches production code — fillable only by doing the architecture thinking; `plc-architecture-quality` judges their content and flags their absence as critical):**
  - **Families** — every family extended or introduced, with a one-line axis statement per new rung/variant ("this rung varies X; the base varies Y"). Non-nesting axes must state why the design is not a composed strategy (`architecture_philosophy` §Orthogonal axis).
  - **Authored surfaces** — every new `[Export]` / scene node / BB key / `.tres` field, each with its single home, its named consumer, and its misconfiguration failure mode with the loud mechanism (`_GetConfigurationWarnings` / throw-at-init / lint).
  - **Designer surface** — what the Inspector/scene tree shows an author after this change: what is hand-configured, what is automatic, what validates it.
  - `None — <reason>` is a valid section body (e.g. pure retirement); an absent section is not.
- **Two harness-bearing sections (REQUIRED instead, on a `meta` plan — one that writes only `.claude/**` or docs; `plc-instruction-quality` and `plc-doctrine-consistency` judge them):** the three above have no referent on markdown, and a plan that answers them `None` four times is filling in a form rather than doing the thinking.
  - **Surfaces touched** — every harness artifact edited, each marked always-loaded or on-demand, with the citations pointing at it (renames, moved sections, and renumbered `§N` are what rot). Always-loaded additions state what the new bytes outrank.
  - **Verification** — per artifact, the named check that proves the edit works: hook compiles AND fires on a crafted input, script runs its success and failure paths, renamed key has no stale references, cited path resolves, battery still passes, JSON still parses. "Reviewed the diff" is not a check.
- **Closing steps (Definition of Done)** — the Part's close-out sequence: gate → commits → roadmap flip (exact content per the driving command).
