# Plan-file format (shared)

What a plan file must read like — the artifact presented for the user's approval and that [`/plan_handoff`](../../commands/plan_handoff.md) / [`/part_execute`](../../commands/part_execute.md) execute. Referenced by [`/part_drive`](../../commands/part_drive.md), those two, and CLAUDE.md.

A plan file is a **context-free execution document** — for a cold reader (the executor, AND the user reviewing it for approval) who wants the final realized procedure, not the discovery history.

- **Resolved design as fact.** Never "the design said X, we changed to Y" — write Y. A prototype-settled answer is one of these facts: pin it under `Constraints` citing `prototypes/<slug>/ANSWER.md`, never restate it as a question the executor re-decides.
- **Constraints cite their evidence, never copy it.** The `Constraints` section names the `/explore` dossier path, then lists each constraint as its dossier claim id plus a one-line statement. `/plan_check`'s memory lens reads the quotes from the dossier, so copying them only lengthens what every reviewer re-reads. A constraint no dossier holds, such as a user ruling or a hand memory search, carries its own evidence quote.
- **Plan size follows the work.** Every reviewer and the executor read the whole plan, so it carries what they need to act and cites evidence by dossier id. Keep cohesive slices in one plan while the complete plan fits its reviewers and executor. If it cannot be planned and reviewed whole, the split is `drive_spine.md` §Halts H2's.
- **Milestones.** A plan triaged at size ≥ milestones groups its slices into milestones, each ending at a verifiable state the drive reports (`execution_depth.md` §Paths are outputs).
- **Load-bearing facts carry their verification.** A fact the plan depends on is verified in the plan, or assigned to a named spike or test. A count of repo entities — files touched, implementers, call sites, inheritors, scene nodes — carries the method that produced it (`LSP findReferences`, an inheritor sweep, an explicit glob), or is written `unknown — not enumerated`. An estimate offered as the basis for a go/no-go decision is the failure this prevents. **`unknown` is a legal record, never a legal bound** — a plan may not claim a bounded file list on a count written `unknown`, and the drive spine's H2 ([`drive_spine.md`](drive_spine.md) §Halts) halts on an unbounded list, so a plan that needs the bound enumerates first.
- **Rationale woven inline** at the decision it justifies (one concise clause where a choice is non-obvious or dodges a named gotcha), in the relevant section/slice — never a trailing "Decision record" dump or a leading "Scope resolution" preamble.
- **Decision promotion is gated; recording is not.** Record rationale inline liberally — it costs one clause. Carrying a decision PAST the plan (promoted at plan completion to the design doc or a memory rule) requires all three: **hard to reverse**, **surprising without context**, **the result of a real trade-off**. Miss one and it dies with the plan — an easy reversal just gets reversed, an unsurprising choice raises no questions, and a decision with no real alternative records nothing but "we did the obvious thing".
- **Focus deviation is marked in the header, verbatim.** A plan whose work is paused by `Claude/Meta/Development-Focus.md` — or that pulls scope forward against it — opens its header block with a line starting `**Focus note (advisory):**`, naming what the focus pauses, the force that overrides it, and that it is advisory rather than blocking. Use that literal string when manually recording the deviation under `Development-Focus.md` → `## Focus deviations`. Not deviating → no line.
- **No process-meta sections.** The drift, critique and convergence narrative belongs in the approval-presentation message (`commands/part_drive.md` §Close), not the plan.
- **No open user-decisions at approval.** Presenting the plan asserts it is ready; an unresolved fork means it isn't. Resolve every fork needing the owner before presenting, as one batched packet (`CLAUDE.core.md` §Preferences), and write the picks in as fact. Under explicit unattended authority a reversible fork with a recommendation is decided provisionally and recorded in the plan instead of blocking. Executor-latitude (an implementation detail the executor settles at code-time) may be stated as latitude — that is not an open question.
- **Pre-agreed seams, caller first.** The plan names the contract each slice hands the next — signature, owning type, call direction — before slice 1 starts, and writes the consuming call site as it will read BEFORE the signature that serves it. Call *direction* is not the caller's *usage*; a seam whose caller was never written is a signature guess. The contract itself is `design_litmus` #7. An executor that must decide a seam mid-slice is reading a defective plan: it reports the gap rather than inventing one.
- **Slice shape.** The shape rules (green alone, a tracer first slice, expand–contract for a wide mechanical refactor) are [`drive_spine.md`](drive_spine.md) §Slices'; the plan records which shape it uses. Every slice carries a one-line **test intent**: the named failing test that gates it (Logic domain), the ISceneRunner assertion (Gameplay), or an explicit `subjective — <who judges>` (a playtest, the owner, a review seat).
- **Root acceptance.** A plan serving an owner's goal maps each requirement and exclusion it serves in the goal's task record (`orchestration` reference `checkpointing.md`; record any it lacks with `task_record.py add <task> requirement|exclusion`) to a row: slice → test intent → rendered scenario → the judgment only the owner makes, or `none`. A rendered scenario is the real scene with its real sensors, collisions and default settings, and what a retained run log or capture of it must show, across each state the behavior crosses (a target still, moving, lost and reacquired). Parallel plans serving one goal share its task record, and each requirement needs a row in one of them; `drive_spine.md` §Close verifies their union.
- **Write each test intent so it fails until the slice's unknown is resolved correctly** (`orchestration` reference `slice_pins.md` defines a scoring check, and §5 pins from this field). Put the scoring step, a hand-labeled sample, in the plan before the slice that tunes against it, or split the slice out as a `subjective` job.
- **Self-checked before hand-off.** The plan settles what its drafter's own reads settle (`orchestration` §Goal). Select `/plan_check`'s deterministic instruments by the plan's claims and surfaces: `extract_numbers.py list` for numeric claims, `restate_scan.py pairs --text <plan> --json` for rule changes, and `verify_doc_citations.py --kinds path,command --json --only missing` for referenced paths and commands. For every replaced surface, sweep its consumers (`citers.py --plan <plan>` on a meta plan; the code-navigation route (`CLAUDE.coding.md` §Semantic Search MCP) on a code plan) and read the callers. Confirm each unknown left open needs an execution result to settle; a test's fixture values, a behavior's boundary values and the inputs a seam's stated behavior reads are unknowns too (`plan_check_agents.md` plc-test-readiness, *Executor decisions*, checks them). Fix each applicable hit before hand-off. Review then spends its seats on design, not on facts the drafter could read.
- **Model attributes are cited, never copied.** A job map names each job's model family and its work class (ambiguous or clearly defined, per `orchestration` §5), then points at the ladder cell (`reference/model_ladder_evidence.md` §Role guidance) for its effort. A copied effort level, capability claim or version note goes stale at the owner's next ladder revision. An ambiguous row names its unknown, how execution settles it (a probe, experiment or test), and the bounds of the executor's choice; a finding outside those bounds is a halt.
- **Out of scope (REQUIRED section).** One-line entries naming what this plan deliberately does not do, including anything the design parked. `None` is a valid body; absence lets every reviewer re-litigate the boundary.
- **One shape per plan file.** Partition separable code/meta work into one plan per shape, audited together through `/plan_check`. For inseparable work use its Mixed shape, which includes code mandates and the meta instruction-quality and doctrine-consistency lenses. Harness commits run quick checks and close proofs under `rules/harness_tooling.md`. Harness edits made *in service of* a production change (a domain row added because a new subsystem landed) are not a second shape: they have no deliverable apart from that plan.
  **Shape is the only hard partition; granularity within a shape is a cohesion and fit call.** Default to one plan per shape and split further only when items stop sharing a plan's spine or a required reviewer/executor cannot read the complete plan within usable context. The cohesion litmus is whether one `Constraints` block and one `Verification` section genuinely cover them all. Two mechanical chores share a plan; two dense items that would each need their own constraints, their own seams, and their own verification are two plans already, and filing them as one degrades the exact sections `/plan_check` reads hardest. Splitting costs another plan audit and review context, so let cohesion and full-input fit decide it — never item count.
- **Three architecture-bearing sections (REQUIRED on a plan that touches production code — fillable only by doing the architecture thinking; `plc-architecture-quality` judges their content and flags their absence as critical):**
  - **Families** — every family extended or introduced, with a one-line axis statement per new rung/variant ("this rung varies X; the base varies Y"). Non-nesting axes must state why the design is not a composed strategy (`architecture_philosophy` §Orthogonal axis).
  - **Authored surfaces** — every new `[Export]` / scene node / BB key / `.tres` field, each with its single home, its named consumer, and its misconfiguration failure mode with the loud mechanism (`_GetConfigurationWarnings` / throw-at-init / lint).
  - **Designer surface** — what the Inspector/scene tree shows an author after this change: what is hand-configured, what is automatic, what validates it.
  - `None — <reason>` is a valid section body (e.g. pure retirement); an absent section is not.
- **Two harness-bearing sections (REQUIRED instead, on a `meta` plan — one that writes only `.claude/**` or docs; `plc-instruction-quality` and `plc-doctrine-consistency` judge them):** the three above have no referent on markdown, and a plan that answers them `None` is filling in a form rather than doing the thinking.
  - **Surfaces touched** — every harness artifact edited, each marked always-loaded or on-demand, with the citations pointing at it (renames, moved sections, and renumbered `§N` are what rot). Always-loaded decision additions satisfy `instruction_quality` §5's admission and byte-delta checks. A fenced ```` ```surfaces ```` block lists each renamed, rewritten or deleted surface, one JSON object per line, which [`citers.py`](../../tools/citers.py) sweeps and `lens_briefs.py` requires on a meta plan: `{"kind": "path|section|key|symbol", "surface": "<see below>", "change": "rename|rewrite|delete"}`, plus `"to"` on a rename.
    - `path`: a repo-relative file that exists at HEAD.
    - `section`: `<path> §<anchor>`, where the anchor equals a heading's text at HEAD without its `#` marks, or a bullet's bold lead label (`**Self-checked before hand-off.**` is `Self-checked before hand-off.`). Never a line number: lines drift.
    - `key`: a literal token searched as a fixed string: a lens, rule, hook or schema key, a verdict word, a placeholder.
    - `symbol`: `<path>::<name>`, a function, class or constant defined in that file.
  - **Verification** — per artifact, the named check that proves the edit works: hook compiles AND fires on a crafted input, script runs its success and failure paths, renamed key has no stale references, cited path resolves, battery still passes, JSON still parses. "Reviewed the diff" is not a check.
- **A short plan keeps its shape's required sections as one line each.** A plan that plan check does not admit (`execution_depth.md` §Admission table) writes each of the three architecture sections, or a meta plan's two harness sections, as "N/A — design = settled (triage record: <the fact that settled it>)". The section is still present, so the absence rule above stands.
- **Closing steps (Definition of Done)** — [`drive_spine.md`](drive_spine.md) §Close owns the close sequence; the driving adapter names its own entry point.
