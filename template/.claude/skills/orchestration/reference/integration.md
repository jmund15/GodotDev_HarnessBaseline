# Integration: a running or returned dispatch

## While a job runs

Message a dispatched agent only when it changes its next action, with the evidence path and the requested action; a running Workflow or sidecar author job has no inbox, so write its brief's full file name plus `.amend.md` (`S.md.amend.md` for `S.md`); its engine's line has the job Read it at each item and before returning. A message may resume a finished agent; do not reopen a completed audit or review files still being edited. Never edit a running fold's subject or writer's write set: wait for its result, or use a worktree.

## When it returns

`dispatch.js` checks declared returns and recognized claims/findings fences against `reference/evidence_contract.md` and returns a `verification` block with applied verdicts. A job declaring `fold: {findings, digest, snapshot}` or `ledger: {stage, subject, roster, scopeJson}` selects its review closure. The parent checks each required standalone findings/claims deliverable's schema and completeness and runs its applicable `tools/post_check.py` route when no checked block was produced. In review mode the report carries fold results, held items, failures, ledger rows and `nextRound`; the parent rules these per `commands/agents/orchestrator_action_protocol.md` Step 1.5. Preserve original findings and provenance on integration (Step 1 there owns location versus defect identity). The Stop audit recomputes checked verdicts and blocks on a mismatch or an unapplied verdict.

Compare intent with what ran. Before dispatch, write the announced job list (label, model, effort, transport, role per job) as the manifest seed; after the run, build the manifest (`orchestration_metrics.py --manifest-seed`). Record each `drift` entry and each label the manifest refuses in that job's rating note. A missing label, or a brief mandate with no returned seat, is UNCOVERED (`orchestration` §2's coverage rule).

Recover before another paid call (artifact, then transcript or `/salvage_fanout`), and confirm a job is terminal before replacing it. Rate each result on consumption (`/orchestration_metrics` §Incremental rating).
