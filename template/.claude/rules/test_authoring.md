# Test Authoring (fires on Tests/ touches)

Full doctrine: `testing` skill `reference/choosing.md` §Test Subject Selection + §Retention & Curation Policy.

1. **Scene addressing — never direct-child-by-name off a scene root.** Resolve production nodes by type (`GetFirstChildOfType<T>`), by `%UniqueName`, or via a NodePath the scene exports. Hardcoded `GetNode("SystemName")` couples the test to topology and taxes every future scene refactor. *Exception:* when topology IS the declared subject — say so in the test's `<summary>` so a refactor knows the coupling is load-bearing, not incidental.
2. **Double reuse.** Before hand-rolling a fake/spy/mock/fixture, check (a) for a **concrete production type** that already answers it — a preconfigured Resource, a shipped `Dir8*`/`Default*` instance — then (b) `Tests/Framework/Mocks/`. An empty `Mocks/` is not clearance to author; (a) is the step that gets skipped, and a hand-rolled copy of a shipping type drifts from the config production actually runs while the suite stays green. On the SECOND use of any double, promote it to `Tests/Framework/Mocks/` — a private nested double is only legal while it is the first and only one for its interface.
3. **Subject selection.** Building blocks (components, systems, strategies, behavioral Resources) get thorough logic+integration coverage. Composed entities get one parameterized roster wiring suite + representative full-composition E2Es — never a per-entity logic suite or per-instance resource pin. Data pins are per-SCHEMA (`[TestCase]` roster rows; exemplar: `Tests/Integration/Enemies/NewUnitDataTests.cs`), not per-instance.
4. **Never name a test folder after ANY namespace segment directly under `{{PROJECT_NAME}}.`** — production segments included, not just the `Tests/<X>` siblings (`Fixtures`, `Framework`, `Integration`, `Sanity`, `Stress`, `ProcGenSim`). C# name lookup walks outward from the test's own namespace and stops at the first match, so `Tests/Logic/Spells` declares `{{PROJECT_NAME}}.Tests.Logic.Spells` and shadows production `{{PROJECT_NAME}}.Spells` for every unqualified `Spells.X` in any file under `Tests.Logic`; the `CS0234` names a file you never opened. **The same shadowing applies within a single file:** a suite in `{{PROJECT_NAME}}.Tests.Integration.Casting` cannot write `Casting.CasterComponent` — its own namespace leaf wins — so cross-namespace references in `///` crefs and code are fully qualified whenever the leaf is shared. Put such a suite in an existing non-colliding folder (`Foundation`) or coin a name with no twin. The namespace must still start `{{PROJECT_NAME}}.Tests.Logic.` — `/regression_gate` filters on `FullyQualifiedName~Tests.Logic`.
5. **Curation on touch.** Touching a suite obligates retiring redundant, documentation-only, or duplicate-double coverage in the same change. *Doc-only litmus:* does every assertion consume a value produced by production code? Both operands derived from locally-constructed literals → documentation-only, regardless of how real the setup looks.
6. **Assert the invariant, not the observation — and prove it by breaking the code.** An assertion recording what a run happened to produce (a distance, a position, a count) passes for reasons unrelated to the behavior it claims to pin. Write what must be TRUE, then **disable the mechanism and watch the test fail**; a new assertion that has never been seen red is unverified, whatever colour it currently shows. **A RED is only evidence when its failure names the designed mechanism** — read the failing assertion and its log before accepting it; a RED produced by a fixture defect (late floor, missing wiring) "confirms" any hypothesis equally. *Litmus:* name the one-line change to production code that turns this test red — can't → it pins nothing.

   **Pin a derivation across a sweep, never at the shipped value.** A test exercising a formula at only its production parameter cannot distinguish it from any rival formula that happens to agree there — and rival formulas coincide at exactly one point, which is often the shipped one. Sweep several values including the extremes (`feedback_pin_derivations_across_parameter_sweep.md`).

7. **Pin one production-topology chain per discovery path.** Where production resolves a dependency by *discovery* — ancestor walk, scene search, graph-chain attach — a fixture that hand-wires the result skips the code that can break, and the suite stays green over a topology the game never has. Keep the fast hand-wired tests; add ONE pin per discovery chain built by production's own `_EnterTree`/wiring over the real tree layout, disjoint subtrees included. The substitution axis is not only topology: a mock of a production *intermediary* hides that intermediary's bugs — fake the LEAF dependency and keep every layer above it real (`feedback_test_fixture_must_match_production_topology.md`).

8. **Load a stateful `.tres` with `CacheMode.Ignore`.** `GD.Load`/`ResourceLoader.Load` cache by path, so a `.tres` whose *inline sub-resources* hold per-run state (a one-shot latch, an accumulator) hands every test the same stale instance. When ≥2 tests load one such path, use `ResourceLoader.Load(path, "", ResourceLoader.CacheMode.Ignore)` — it re-parses the file for fresh inline sub-resources while ext-resource refs stay cache-shared. The `.tres` itself stays shared-stateless config; the hazard is specifically a stateful inline sub-resource plus the path cache (`gotcha_godot_resource_cache_stateful_tres_test_isolation.md`).

9. **Physics state needs `AwaitMillis`, never `SimulateFrames`.** `SimulateFrames(n)` steps the SceneTree's idle/process loop without advancing the fixed-timestep physics server, so collision pairs never form: `GetOverlappingBodies()` stays empty and `BodyEntered` never fires. Anything depending on physics-server state — Area overlap, `BodyEntered`/`AreaEntered`, `MoveAndSlide` collision, raycasts against live bodies — settles with `AwaitMillis(n)` (~60 Hz, so 200 ms ≈ 12 frames). `SimulateFrames` stays correct for pure process-frame logic (tween, AnimationPlayer, `_Process` state). *Corollary:* synchronously pumping `MoveAndSlide` preserves `Velocity` exactly but does NOT integrate `GlobalPosition`. Velocity assertions are safe synchronously; displacement assertions are not (`gotcha_simulateframes_no_physics_tick.md`).

10. **A superseding fix deletes what it supersedes, in the same commit.** When a change makes an earlier fix, pin, or workaround obsolete, remove it in that change — never leave both and let the suite decide. Two pins for one behavior drift apart silently: the stale one either fails later for a reason no one can reconstruct, or keeps passing and is read as coverage the code no longer has.

11. **A double's Godot base type is set by what CONSUMERS resolve it as.** A typed lookup (`TryGet<Node3D>`, `as`, `GetFirstChildOfType<T>`) filters by type with no physics API, so grepping the double for `MoveAndSlide` proves nothing.

12. **Never pin a production data VALUE, and never demand a field that authored content may legitimately omit.** Assert structure — loads, attribute DEFINED, module wired. Scope a completeness gate by the predicate that makes the field meaningful.

13. **When an e2e fixture is impossible by construction, pin production and routing each at its own layer.** Real fixture for the producer, scriptable double for the consumer — and record WHY no e2e exists, or an audit reads the gap as missing coverage.

14. **A test name promising a branch needs setup that actually reaches it.** A SUT short-circuiting first passes green with the branch untested. Litmus: would deleting that branch red this test? Assert a side effect unique to it.
