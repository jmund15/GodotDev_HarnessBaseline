# Test Authoring (fires on Tests/ touches)

Full doctrine: `testing` skill §Test Subject Selection + §Retention & Curation.

1. **Scene addressing — never direct-child-by-name off a scene root.** Resolve production nodes by type (`GetFirstChildOfType<T>`), by `%UniqueName`, or via a NodePath the scene exports. Hardcoded `GetNode("SystemName")` couples the test to topology and taxes every future scene refactor (24 such lookups blocked the wind/trail template extraction). *Exception:* when topology IS the declared subject — say so in the test's `<summary>` so a refactor knows the coupling is load-bearing, not incidental.
2. **Double reuse.** Before hand-rolling a fake/spy/mock/fixture, check (a) for a **concrete production type** that already answers it — a preconfigured Resource, a shipped `Dir8*`/`Default*` instance — then (b) `Tests/Framework/Mocks/`. An empty `Mocks/` is not clearance to author; (a) is the step that gets skipped, and a hand-rolled copy of a shipping type drifts from the config production actually runs while the suite stays green. On the SECOND use of any double, promote it to `Tests/Framework/Mocks/` — a private nested double is only legal while it is the first and only one for its interface.
3. **Subject selection.** Building blocks (components, systems, strategies, behavioral Resources) get thorough logic+integration coverage. Composed entities get one parameterized roster wiring suite + representative full-composition E2Es — never a per-entity logic suite or per-instance resource pin. Data pins are per-SCHEMA (`[TestCase]` roster rows; exemplar: `Tests/Integration/Enemies/NewEnemyDataTests.cs`), not per-instance.
4. **Never name a `Tests/Logic/<X>` folder after a top-level `Tests/<X>` sibling.** `Tests/` holds `Fixtures`, `Framework`, `Integration`, `Sanity`, `Stress`, `ProcGenSim`. Creating e.g. `Tests/Logic/Framework/` declares `{{PROJECT_NAME}}.Tests.Logic.Framework`, which **shadows** `{{PROJECT_NAME}}.Tests.Framework` for every file under `Tests.Logic` — C# name lookup walks outward and stops at the first match. Unqualified references like `new Framework.Fixtures.TestCombatant()` in *untouched, unrelated* suites then fail to compile (`CS0234`), so the error names a file you never opened. Put such a suite in an existing non-colliding folder (`Foundation`) or coin a name with no top-level twin. The namespace must still start `{{PROJECT_NAME}}.Tests.Logic.` — `/regression_gate` filters on `FullyQualifiedName~Tests.Logic`.
5. **Curation on touch.** Touching a suite obligates retiring redundant, documentation-only, or duplicate-double coverage in the same change. *Doc-only litmus:* does every assertion consume a value produced by production code? Both operands derived from locally-constructed literals → documentation-only, regardless of how real the setup looks.
6. **Assert the invariant, not the observation — and prove it by breaking the code.** An assertion recording what a run happened to produce (a distance, a position, a count) passes for reasons unrelated to the behavior it claims to pin. Write what must be TRUE, then **disable the mechanism and watch the test fail**; a new assertion that has never been seen red is unverified, whatever colour it currently shows. **A RED is only evidence when its failure names the designed mechanism** — read the failing assertion and its log before accepting it; a RED produced by a fixture defect (late floor, missing wiring) "confirms" any hypothesis equally (measured: a test went RED for a fixture-timing defect, not the threshold it claimed to pin). *Litmus:* name the one-line change to production code that turns this test red — can't → it pins nothing. Measured: a shed-fling test asserting world-Y rise passed with the arc entirely removed, because the entity also rose from host motion and its own recoil; the honest pin was a unit assertion on the resolved direction, which went red on the first probe.

   **Pin a derivation across a sweep, never at the shipped value.** A test exercising a formula at only its production parameter cannot distinguish it from any rival formula that happens to agree there — and rival formulas coincide at exactly one point, which is often the shipped one. Sweep several values including the extremes. The pin measures a coincidence otherwise: green suite, wrong derivation everywhere else, failure surfacing only when someone tunes the parameter, far from the change that caused it. Never pin a production data VALUE as the expected result (`feedback_pin_derivations_across_parameter_sweep.md`).
7. **Pin one production-topology chain per discovery path.** Where production resolves a dependency by *discovery* — ancestor walk, scene search, graph-chain attach — a fixture that hand-wires the result skips the code that can break, and the suite stays green over a topology the game never has. Keep the fast hand-wired tests; add ONE pin per discovery chain built by production's own `_EnterTree`/wiring over the real tree layout, disjoint subtrees included. The substitution axis is not only topology: a mock of a production *intermediary* hides that intermediary's bugs — fake the LEAF dependency and keep every layer above it real. Measured: fixtures attached a child graph straight to the root graph where production goes child→runtime-owner→root; every gated child shipped empty while the suite passed (`feedback_test_fixture_must_match_production_topology.md`).

8. **Load a stateful `.tres` with `CacheMode.Ignore`.** `GD.Load`/`ResourceLoader.Load` cache by path, so a `.tres` whose *inline sub-resources* hold per-run state (a one-shot latch, an accumulator) hands every test the same stale instance. When ≥2 tests load one such path, use `ResourceLoader.Load(path, "", ResourceLoader.CacheMode.Ignore)` — it re-parses the file for fresh inline sub-resources while ext-resource refs stay cache-shared. The `.tres` itself stays shared-stateless config; the hazard is specifically a stateful inline sub-resource plus the path cache (`gotcha_godot_resource_cache_stateful_tres_test_isolation.md`).

9. **Physics state needs `AwaitMillis`, never `SimulateFrames`.** `SimulateFrames(n)` steps the SceneTree's idle/process loop without advancing the fixed-timestep physics server, so collision pairs never form: `GetOverlappingBodies()` stays empty and `BodyEntered` never fires. Anything depending on physics-server state — Area overlap, `BodyEntered`/`AreaEntered`, `MoveAndSlide` collision, raycasts against live bodies — settles with `AwaitMillis(n)` (~60 Hz, so 200 ms ≈ 12 frames). `SimulateFrames` stays correct for pure process-frame logic (tween, AnimationPlayer, `_Process` state). *Corollary:* synchronously pumping `MoveAndSlide` preserves `Velocity` exactly but does NOT integrate `GlobalPosition` — measured 0.178 m from a 31-tick synchronous pump vs 2.583 m with physics frames interleaved, at identical velocity. Velocity assertions are safe synchronously; displacement assertions are not (`gotcha_simulateframes_no_physics_tick.md`).

10. **A superseding fix deletes what it supersedes, in the same commit.** When a change makes an earlier fix, pin, or workaround obsolete, remove it in that change — never leave both and let the suite decide. Two pins for one behavior drift apart silently: the stale one either fails later for a reason no one can reconstruct, or keeps passing and is read as coverage the code no longer has. This is why a superseding change is not done when it goes green — it is done when the surface it replaced is gone.
