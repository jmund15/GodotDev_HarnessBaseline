# Sidecar runs after launch

What happens once a sidecar run starts. `reference/sidecar_dispatch.md` owns launching; read this file when a run ends, refuses, stalls or wakes you.

## Resume — the two endings a run can be rescued from

**Resume is not retry.** `--resume <sid>` continues the same session and keeps every turn already paid for; a fresh dispatch re-buys them. That is what puts this inside the standing rule against auto-retrying a billed call, not against it — the rule bans duplicating spend. No session id means nothing to resume, and the launcher must not re-issue the run.

`sc_resume_loop` (in `lib/sidecar_common.sh`, called by every launcher) classifies the finished stream with `tools/sidecar_resume_check.py` and re-invokes the same child with `-r` plus the brief on stdin while each resume adds work after its boundary (`SC_COMPACT_RESUMES` caps the count). It stops and reports when a resume ends at a boundary with no new tool calls. **stream-json only** — `-o json` emits no `compact_boundary` and no per-event stream, so a non-stream run prints a resume-unavailable diagnostic and stores its ending as the deliverable; `-P` sets stream-json. When the budget is exhausted and the run is *still* resumable, the launcher says so loudly: a run that burned its resumes otherwise records exactly like one that finished.

| ending | detected by | why resuming is safe |
|---|---|---|
| **compaction** | `compact_boundary`, zero tool calls after it, result opens `<analysis>`/`<summary>` | the child answered the continuation summary instead of the task; the work is intact in the session |
| **transient** | `is_error` + a connection-level signature (`WebSocket stream error`, `Connection reset without closing handshake`, `os error 10054`, 502/503/504) | the upstream stream aborted mid-flight after a 200; nothing about the request was rejected |

Never resumed, because each loops or needs backoff the loop does not implement: unknown model, malformed request, 401/403, rate limit or quota. The detector checks these **first**, so a deterministic fault can never be read as transient.

A mid-stream abort logs upstream as `status=200` (the proxy records status at headers, not at stream end), so diagnose it from the child's `terminal_reason` and `traffic/<session_id>/`, never from `proxy.log`.

## Provider usage limit

The first usage-limit retry the launcher sees writes `<record>.usage` (first-seen time, transport, retry count, the provider's reset time when the stream carries one) and the run keeps retrying; the session watcher wakes on it, so a blocked seat is known at once. A 429 run that clears within one watch poll is not marked.

A usage-limit rejection ends the run. The launcher detects the child's terminal usage-limit result (any terminal 429, the 5-hour window's `session limit` included), or `SIDECAR_USAGE_LIMIT_RETRIES` (default 10, the CLI's own `max_retries`) consecutive 429 `api_retry` lines with no work event between them. It kills the child, never resumes it, records `stopReason: provider-usage-limit` with `usageLimitResetsAt` and `rateLimitInfo` when the stream carries them, appends the ledger row and exits 10. Retry and other system lines are not progress for `-Z`.

A terminal result ends the run too. `claude -p` stays alive after its result while a background task it started runs, and each task's end re-wakes it for a billed turn. The launcher ends a child still alive `SIDECAR_RESULT_GRACE_SEC` (default 30; 0 turns it off) after its first result, keeps that result's exit code (0 success, 1 error) and writes the record. The grace needs a stream to watch: `-R` and `-P` runs have one. `-R` with `-o json` streams internally and prints the one result object; a run with neither `-R` nor `-P` has no grace.

The first stop writes the exhausted marker `~/.claude/sidecar-exhausted/<transport>.json` (`SIDECAR_EXHAUSTED_DIR` moves it). It expires at the stream's reset time, or at the fallback timestamp `sc_mark_exhausted` writes when no reset is reported. Expiry permits another admission check; it is not evidence that provider capacity recovered. While it is live, every launch and `--check` on that transport exits 10, and neither `-A` nor `-U` overrides it. Owner override: delete the marker, only on the owner's word.

A stopped run keeps its session (`sessionId` in the record) and every edit it made. Pick the route by cost: resuming after the reset (`-r <sessionId>` on the same transport; a fan-out job passes it in `extraArgs`) keeps every paid turn and the run's knowledge of its own edits, while another provider re-buys the work and must first re-verify the stopped run's unreported edits. Resume when the reset comes before that re-bought work would finish; otherwise route the rest to another provider, with a brief that names the stopped run's edits.

`python3 .claude/tools/sidecar_fanout.py --status <out-dir>` prints one line per job from its latest attempt: `working`, `retrying`, `stalled`, `finished`, `usage-limit` or `output-cap` (the client resumed past, or the final message outgrew, the child's output-token cap: check the row's `maxOutputTokens` via `model_registry.py max-output`), `lingering` when the launcher is still alive `RESULT_LINGER_S` seconds after its stream's result (`tools/sidecar_resume_check.py` owns the value; the session watcher wakes on it as `LINGERING`), or `died` when a detached child's pid is gone with no `.exit`. The fan-out summary reports a usage-limit stop as `usage-limit` and names the stream to salvage from, and a final message past the cap as `output-cap` with the cap's size; an unchanged rerun fails the same way.

### Compaction specifics

After auto-compaction the child receives the summary as a user message and, unanchored, answers it and ends. Every Claude-client launcher merges `hooks/sidecar_recompact_reprompt.py` (SessionStart, matcher `compact`, and PreCompact) into `--settings` through `scripts/lib/sidecar_common.sh`, preserving existing hooks, including benchmark guards. After compaction it re-injects the original `-f` brief; its docstring owns the details. `SIDECAR_COMPACTION_RAIL` picks the summary text per launch (`selected_rail`; unset or unknown is the default rail), and the record stamps it as `compactionRail`. `scripts/codex_proxy_sidecar.sh` keeps its existing `CLAUDE_CODE_SIDECAR_PROMPT_FILE` registration; the shared merge does not duplicate it. Native `opencode run` does not use Claude hooks.

- Registration rides with the LAUNCHER: a worktree checked out before the hook existed gets no re-prompt.
- What ends a run is the thrash breaker, not a compaction count: a run reports `terminal_reason: rapid_refill_breaker` after a rapid context refill; inspect the session and reduce the next result's read footprint before recovery. Keep single tool results sized to the decision: use `-D pointer` or bounded `Read` ranges when sufficient; read a whole resource or patch when its content is required and fits the receiving context.
- Every launcher except `codex_proxy_sidecar.sh` sets the child's output cap (`CLAUDE_CODE_MAX_OUTPUT_TOKENS`) from `model_registry.py max-output`: the row's own `maxOutputTokens`, at most a quarter of its registry window. A launcher that declares a window in place of the registry's (`deepseek_sidecar.sh` under `MAX_CONTEXT_TOKENS`) bounds the cap at a quarter of that window. The client's 32000 default discards a paid reply that outgrows it, reasoning included. A row with no sourced maximum keeps its launcher's default; source the row's `maxOutputTokens` rather than raise a per-job number. A numeric `SIDECAR_MAX_OUTPUT_TOKENS` overrides; a non-numeric one is reported and ignored.
- `codex_proxy_sidecar.sh` keeps its own 16000 default, because its cap also sets the output reserve it subtracts from the declared window, and that default comes from a measured compaction point. `SIDECAR_MAX_OUTPUT_TOKENS` overrides it, and `SIDECAR_OUTPUT_RESERVE` overrides the reserve alone.
- Anthropic launchers use `tools/model_registry.py anthropic-window`; `anthropic_window` owns the binary-derived formula. `CLAUDE_CODE_AUTO_COMPACT_WINDOW` makes the child compact at `limits.compactAtTokens`, or keeps the effective window when that input operating point is absent. `[1m]` is requested only on rows declaring at least 1M context; it changes neither served model nor registry price tier. Non-Claude names keep `CLAUDE_CODE_MAX_CONTEXT_TOKENS`.
- Anthropic records and the turn-1 percentage use the enforced auto-compact window, or `null`/`window unknown` when it cannot be established.
- `-K <tokens>` sets the Anthropic child's compact point: the input size at which it compacts, in the unit of the registry's `compactAtTokens`, which it replaces (`anthropic_window(compact_override=...)`). The launcher adds the client reserve (the output cap up to 20000, plus 13000) to derive the client window, which must fall in 100000..1000000. `SIDECAR_COMPACT_AT_TOKENS=<tokens>` is the same knob (the flag wins), Anthropic-only. Set it above the child's post-compact load, which this harness's doctrine and restored files put near 50k–80k; below it the client's refill breaker ends the run. The record adds `contextOverride: <window>` beside `contextWindow`; without an override it adds no field.
- Benchmark dispatch flags carry the override to every cell. Stamped pins display an exact window suffix such as `[1M ctx]` and rank only within that window's cohort. Default task leaders, cheapest-competent verdicts, readiness, health, coverage advice and `bench next` use unstamped rows. Matrix, spread, usage and lifetime views keep both pins visible, never pooled. Use a separate campaign name for each arm; verify `turn1ContextTokens` and usable window for the actual job.

## Detached runs

- **Live until proven gone.** A run with `-R` and no `<record>.exit` may still be live: once `-R` is parsed, its EXIT trap writes the marker if the output directory remains writable. Pre-parse errors and an unwritable directory are exceptions, so check the process before deciding. A parsed `-R` also names the launcher in `<record>.pid` as `<UTC stamp> [launch=<id> ][winpid=<N> ]pid=<N>`; a detached run's last line names the job. Check `winpid` with `Get-CimInstance Win32_Process` on Windows, or `pid` with `kill -0` in the same MSYS/POSIX shell, and compare creation time with the stamp. No form deletes its files; a relaunch takes a new `-R`.
- **What wakes you.** The session watcher (`reference/sidecar_dispatch.md` step 6) exits on the first of: a job ending non-zero or dying (except one you stopped with `reap.py`, which prints `STOPPED <label>` at the next wake; a unit you stopped whole wakes nobody), a memory refusal (exit 12) included; a job writing `<record>.stall` while its provider traffic is older than `watch_records.UPSTREAM_LIVE_S` (a fresh-traffic stall is a reasoning turn and prints at the next wake); a job writing `<record>.usage` (`USAGE-LIMIT <label> <transport> resets <time|unknown>`); a fan-out process dying with jobs still queued; every job of one dispatch unit ending; a launch with no record `UNRESOLVED_GRACE_SECONDS` after it was issued (`UNRESOLVED`: check its launcher process before relaunching, since it may only be slow); or a run that died while a process still carries its launch id (`ORPHAN <label> launch=<id> pids=<...>`, even when it stood at arm: stop those pids with `reap.py --reason orphan`). While work still runs, it also exits 50 minutes after arm (`CHECKIN`, inside your one-hour prompt cache and before its idle compaction, so the wake reads the cache instead of rewriting it), printing each running sidecar's age and last write with a `progress:` clause under it, and each running Workflow run as `RUNNING workflow <name> <runId> <pins> for <n> min, agents <k> of <m> done` with a clause per running agent. The `CHECKIN` text states how to judge each job from its clause and what to do with one that is not converging (`watch_records.CHECKIN_RULE`). Judge each job from its clause, and from `python3 .claude/tools/watch_records.py --digest <record or transcript>` when the clause is not enough (a Workflow agent's transcript is under its run dir). Then re-arm. A Workflow run's end is not a wake of its own: when the last running job ends the watcher exits `NONE` beside the run's completion notification. `NONE` is a no-action answer, as is `COVERED`. A successful job whose unit still runs wakes nobody — its line prints at the next wake. It reports `DONE` when a nonempty `.exit` is readable. The parent checks output readability and required completion separately before accepting delivery. It reports `DIED` on proven process death and warns `NO-IDENTITY` without treating an unproven launch as dead. A detached job's memory wait prints `WAITING-MEMORY <label>` and both readings at the next wake but wakes nobody: the job launches on recovery by itself, and a wait that never clears shows at the `CHECKIN` (exit 12's bound is in the table below). A fan-out unit stays open while its driver process lives, so a review ends at its fold and post-check, not its last seat. A roster's clean end waits while another roster of this session is live.
- **A stalled run.** `SIDECAR_STALL_SEC` (default in `scripts/lib/sidecar_common.sh`) is a signal, not a kill, and belongs above the longest silence seen on healthy runs of that transport: a `-P` run silent that long gets `<record>.stall` and keeps running, and the next work event deletes the marker. On a `STALLED` wake, inspect that job's progress stream, process and current upstream traffic. Re-arm the session watcher while it can progress. To stop it, choose an idle threshold from the healthy-run evidence and pass it explicitly: `python3 .claude/tools/reap.py --reason stalled --log <record>.stall --idle-min <minutes>`. The marker's idle value must meet that threshold; status heartbeats can keep the stream's mtime fresh.
- **Slow is not stalled.** Stall duration, total budget and model compute are different limits. Before blaming a slow local model, read the ledger and the Ollama completion evidence. Before relaunching a billed failure, recover the usable output from its record, `.out` and progress stream.
- **Harness notices.** A sidecar is watched by that step 6 command, never by its launch's own shell or by a Monitor: a killed notice takes the shell, not the launcher or the child. If a watcher is itself stopped, `sidecar_watch_rearm` re-names the uncovered records and that command after the notice. Streaming `watch_records.py` without `--session --wake` is a live view for a present user only, never the wake route. Check the reported records before relaunching anything.
- **A launched run finishes.** Its tokens are already spent, so a pin mistake is fixed at the next dispatch and in its rating, never by a relaunch. Stop a run only when its output itself would be wrong (a wrong brief or premise): stop it first with `python3 .claude/tools/reap.py` and wait for its `.exit`, then relaunch. Before relaunching, the parent stops the previous attempt's identified process tree and checks for remaining writers. The duplicate-launch guard (exit 13) detects a live launcher or identifiable `claude -p` child running the same job; it does not certify that every seat or leftover server is gone. Never run a twin beside a writer: two runs writing one artifact interleave their edits.

## Exit codes

| code | meaning | fix |
|---|---|---|
| 1 | `-X`: record path already used, or the snapshot could not be made | pass a new `-R` path; check `TEMP` |
| 2 | bad flag / unknown alias / registry unreadable; `-X` without `-R` or inside a flag cluster | `model_registry.py available` |
| 3 | credential/authentication refusal; the native OpenCode preflight also uses it for catalog or permission-probe refusal | read the refusal reason and repair its named cause; do not infer a credential failure from the code alone |
| 4 | child CLI or proxy missing | `<launcher> --check` |
| 5 | current seat's live plan band is below the model floor | `-A` only for deliberate off-quota spend |
| 6 | live target balance is below its floor | replenish funds; not overridable |
| 7 | model marked unavailable | re-select; `-U` only on the user's word |
| 8 | target capacity unavailable/malformed/unsupported-required, or a plan-quota window whose band is unreadable | fix the capacity evidence or the credential |
| 10 | before spawn: dispatch floor, spent allowance or live exhausted marker; after spawn: provider usage limit | read the refusal, wait for its reset or use a plan with room; a stopped session resumes on its own plan (§Provider usage limit) |
| 11 | peak pricing window refused (`gate.peakPolicy: refuse`) | wait for off-peak (`model_registry.py price-window <model>` prints the end); `-W` only on the user's word |
| 12 | foreground memory admission refused, or a detached job's opt-in `-T` / `SIDECAR_TIMEOUT` memory wait bound expired; no model child started | use `-X` for automatic waiting and launch on recovery; the session watcher and fan-out `--status` show the wait and readings. Without a supplied bound, the wait is unbounded. Fan-out still waits before launch and retries 12; no flag overrides the floors |
| 13 | a live launcher or seat child already runs this job (this `-f` prompt file under the same `-l` label or `-R` record) or resumes this `-r` session (`reap.py live-launch`); nothing started, stderr names each PID, launch id and age with the reap command that stops it. Jobs that share a brief under their own label and record (an A/B's arms, one fan-out's jobs) are different jobs and do not refuse. The check itself failing (any exit but 0, 3 or 4) also refuses, with its error on stderr | stop the old run with the printed command, confirm none remain, then relaunch; for a failed check, fix the error it printed first; no flag overrides it |

9 is retired; a stall writes `<record>.stall` instead. Never reuse it.

`--check` exit 0 means preflight passed. A Claude-client launch still runs its profile, brief, memory and duplicate-launch checks before starting the child.
