# Semantic Search — Mechanism Reference

Semantic search answers where an unnamed concept lives (docs, memory, assets, configuration, scripts); Grep and `git grep` own the occurrences of a known exact name, field, path or pattern. Grounding a design with explicit coverage goes to `/explore`. Before claiming absence from an empty search, confirm the scope with git-aware enumeration. This file holds the mechanism behind the tool and its result caveats.

- **Result caveats:** heading-mention chunks can outrank canonical definitions — sharpen with `restrictToDir`. For broad discovery, search facets separately.
- **Engine:** DreB `semantic-search` plugin (installed version: its cache folder name). Tree-sitter chunks GDScript, Python, JS/TS, C/C++, Go, Rust and Java, plus C# where the local shim is installed (`semantic_search_idle.md` §C# AST hook). Other text files and configs chunk as plain text. Ranking is embedding similarity plus 6-signal POEM re-ranking.
- **Indexed:** `.gd` `.py` `.js` `.ts` `.md` `.tres` `.tscn` `.godot` `.json` `.yaml` `.toml` `.txt` `.cfg` `.env`, and `.cs` only through the running shim: a stock or older backend omits C#, so a C# "where is X" question then returns only docs and scenes that mention X. Skipped: binaries, `.uid`, `.import`, anything gitignored, and paths in the root `.searchignore` (gitignore syntax): find a listed path by name with Grep or `git grep`.
- **Index file:** `.search-index/search.db` (gitignored). Each search scans for new, mtime-changed and removed files and embeds their chunks before ranking, and the engine runs one search at a time per root. Use `/reindex_search` for scope changes or index drift. Linked worktrees use the [primary index and local-read contract](semantic_search_idle.md#linked-worktrees).
- **Busy root:** a `rebuild: true` search, or the first search of a root with no index, embeds every chunk first, and every other search of that root waits behind it, past the client's tool timeout; on a large repo that takes minutes (`semantic_search_idle.md` §Measured). While one runs, look up with Grep, `git grep` or LSP.
- **Roots:** `searchDir` is the project root, a submodule or worktree root inside it, or one of the design-source roots the project's `CLAUDE.md` names. Narrow a query with a POSIX `restrictToDir` relative to its index root. A repo index cannot search the vault; a vault search builds `.search-index/search.db` under the selected vault root, so search each named root, never the whole vault or its parent folders. `hooks/semantic_search_scope_guard.py` rewrites a subdirectory `searchDir` to the repo root plus its `restrictToDir`.
- **Cleanup:** a `.search-index/` left under an ordinary subdirectory is stray; remove it unless its SQLite `-wal` or `-shm` file changed within a day.
