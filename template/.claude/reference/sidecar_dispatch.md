# Sidecar Dispatch — one recipe, every transport

A sidecar is a separate client process on a chosen transport. `orchestration` §0 owns route selection: a job on the session's own plan runs as a native Workflow agent, so this recipe covers jobs on any other plan and jobs whose fields need process isolation. Claude-client launchers use `scripts/lib/sidecar_common.sh` for flags, disclosure and recovery. A project's native OpenCode launcher, where it ships one, runs `opencode run` with file attachments and its own permission configuration. Use its flag validation rather than assume Claude-client disclosure, hooks or resume support. The disclosure, tool-profile and permission sections below, and `reference/sidecar_runs.md`'s resume section, describe Claude-client launchers.

## Procedure

1. **Model ladder:** the read-before-pin rule is `orchestration` §5; `hooks/sidecar_dispatch_context.py` denies a launch while the session has not read the ladder since compaction, naming the load route.
2. **Roster + launcher:** `python3 .claude/tools/model_registry.py available` — prints available aliases, roles, effort evidence and paying-plan launchers. Effort displays measured effort levels or an evidence label. Dollar input rates appear only for priced non-plan-quota rows. Launcher = the `launcher` of the plan you chose to pay; `available` names each row's plans and their launchers, and `for-role` names only the plans, never their launch lines. A plan may share another transport's models (`planOf`). The session's own plan runs native; any other plan runs through its `launcher`. Excluded models are out; re-select under the ladder (`reference/model_ladder_evidence.md`) — **a stale route name in a command is not a reason to fall back to the session's own transport.**
3. **Dispatch facts + live capacity:** `<launcher> --check -m <alias> -e <effort> -G <kind> -f <prompt.md>` prints the requested pin, brief bytes and estimated tokens, the kind's tier mapping and matching ladder row with its effort, and the latest rating for that kind's guard and model with its note (or none), then reads the current seat's plan band and the target provider's normalized quota/balance before any model request. A preflight refusal exits before any model request and names its condition; `reference/sidecar_runs.md` §Exit codes owns each code. A plan-quota window never refuses on a pressure ceiling; which plan pays is your choice by the model ladder's selection line. `-A` overrides only the host-band floor. The dispatch hook runs this preflight and denies on any refusal. Before it, the hook runs the Workflow route's tier check (`hooks/_dispatch_checks.py`) on the launch and on each fan-out job: a kind whose tier the alias's row does not serve is denied. Each plan's quota left against its window left is the `[budget-posture]` line, and a row's owner probation mark prints on `model_registry.py for-role <tier>`; both are read before the pin.
4. **Prompt to a file** (never argv — Windows argv caps at ~8K). Schema to a file when you need structured output.
5. **Dispatch** — one call per job, backgrounded or not; every field below is required except the bracketed ones. `-R` and `-l` must resolve to literal tracking values. The hook expands known preceding shell assignments. Unresolved variables and loop-carried values are denied. Several jobs go in a jobs file for `tools/sidecar_fanout.py`.

```bash
bash .claude/scripts/<launcher> -m <alias> -e <effort> -G <scout|lens|reviewer|author|judge> -f <prompt.md> [-S <schema.json>] -R <record.json> -l "<label>" -d "<repo-root>"
```

After `-R` is parsed and its directory remains writable, the launcher's EXIT trap writes `<record>.exit`. Captured output writes `<record>.out`. Detached stdout redirection can create that file empty before the child runs. File existence alone is not captured output. Errors before a valid `-R` may create neither file. A launch ending after its label or `-R` is parsed writes a spend-ledger row unless its resolved ledger path is empty (`-L ""` disables the row). The row uses the published record, or `outcome: ended-before-result` with its exit code and refusal line when no result exists (`finished-without-record` for a finished run without `-R`).

Run it as one command from the project root: no `cd`, `export`, env prefix, redirection or
chaining. A tracked `-G scout`, `-G lens`, `-G reviewer` or `-G judge` launch with a passing preflight and fresh ladder
Read auto-approves only in the narrow `hooks/approving_gates.py` shape: `-R` names a new scratch file, and optional `-P` must do so when supplied. Optional `-L` may name an existing scratch ledger. No `-A`, `-W`, `-U`, `-X` or `-p` grants may be present. Other kinds face the
normal permission checks.

A reviewer requesting exactly `-t +Bash` after `-G reviewer` and before `-f` is **not**
read-only. Its consent shape requires `-m`, `-e`, `-G reviewer`, `-t +Bash`,
`-f`, `-S`, `-R`, `-P`, `-l` and `-d` (optional `-C`), and no `-D`. The hook validates the whole
command, tracked launcher, project paths, model preflight and ladder Read, then returns `ask`.
The project `permissions.ask` rule `Bash(bash .claude/scripts/*_sidecar.sh * -t +Bash *)` guarantees
a visible prompt for every launch it matches, including shapes the hook does not validate; whether
the hook's own `ask` surfaces under auto mode is unmeasured. Approve the **exact command once**, only if shell access for that provider and brief is intended; the rule prompts on every matching launch, so an approval covers that command only. If no prompt appears, stop and reload
settings or start a new session; do not treat a successful dispatch as proof consent was collected.
A wider tool grant or shell compound is not covered.

**Detached form, for a run that must outlive this session:** add `-X -P <progress.jsonl>` and run the call in the foreground. `-X` must be its own argument (never a cluster like `-AX`) and needs `-R`. The launcher starts a detached job and returns within seconds; its own exit is not the run's. Watch it with step 6's command; inspect the process and record before any kill. Each `-R` path takes one launch: a path whose `.out`, `.err`, `.exit` or `.pid` exists refuses with exit 1.

A backgrounded launch is not denied merely for being backgrounded; ladder, capacity, availability, and pricing gates still apply.

6. **Watch — one route for every sidecar, Workflow, bench campaign and long Bash background job.** Arm one session watcher when none of yours is armed: run `python3 .claude/tools/watch_records.py --session --wake` with Bash `run_in_background` and `timeout` 7200000 (the default 30-minute limit ends it before its check-in). Issue a launch and its arm in one message so both calls share one request. A session watcher stays armed while idle, including before the launch entry arrives; `--await-launch` is unnecessary. A re-arm after a wake takes no flag. Do not arm beside a live watcher. A racing duplicate waits to take over instead of exiting and spending a wake on bookkeeping. It re-reads this session's pending sidecars, running Workflow runs, live bench rosters and running Bash background tasks (a task with no end notice counts as live work, so its check-in lands inside the cache window) each poll and wakes you when one
   needs a decision (`reference/sidecar_runs.md` §Detached runs, *What wakes you*). A watcher whose session can no longer receive a wake ends by itself, printing `HOST GONE: <reason>`: its parent shell or the session host that owns it is gone (read from the client's session registry; a client that writes none is never ended on a guess). On a wake, act on its output without a tail or cat call, then re-arm: it carries every job that ended since the last wake (a sidecar, a fan-out job, a Workflow run or a background shell) with its exit, result head, report path and verification counts, then an `UNRATED` line. Decide wake units at launch time: a fan-out job's clean end wakes you,
   because its result is actionable alone (review it, merge it, launch what it gates, triage its offers). A set whose results
   are pieces of one result wakes you once, at its last clean end: the fan-out groups a jobs file with a top-level `measurement`
   (the comparison its jobs make) and its `lens` and `reviewer` jobs by itself. Give other jobs one `wakeWith` group name only
   when no action is possible until every member ends; give every other job no group. Jobs whose results gate a later job are separate fan-outs, and you start the next when you wake. The Stop hook blocks while a running sidecar or a live bench roster this session started has no live watcher unless the payload already sets `stop_hook_active`. When a stopped notice arrives for a backgrounded launch with `-R`, read `<record>.exit` first.
   **Pane, the owner's live view.** Issue `python3 .claude/tools/watch_records.py --pane` with Bash `run_in_background` and `timeout` 86400000 in the same message as a session's first arm, and again when a wake's last lines carry `PANE none`. It appends the running jobs' check-in lines each time they change, so the owner sees the latest state at the tail of that background shell in the CLI and desktop clients; mobile shows no running shell's output. Leave it running and unread: it ends only by `HOST GONE`, as the watcher does, and the watcher does not count it as live work (its docstring owns the behavior).

7. **Consume:** the wake's result head opens the answer; for the whole of it, wait for `<record>.exit` (or prove the process gone), then read
`<record>.claims.json`: its `result` holds the answer and its `claims` carry applied verdicts.
The host writes it and `<record>.post_check.json` before publishing a direct launch's record or
completion, on ordinary and detached paths. Read its `verification` under
`commands/agents/orchestrator_action_protocol.md` Step 1.5; an `unavailable` report is UNCHECKED. The Stop audit reads the same
checked file. `<record>.out` remains unchanged captured stdout for diagnosis, not consumption;
`-o` names its format, not a path. For a long job, include `-P <progress.jsonl>` at launch:
it selects stream-json for compaction/transient recovery. A gate refusal with no captured
output means no answer, not a successful empty review. The `-R` record holds `costUSD`
(list-price tokens; `costBasis` says whether it is spend or a plan-quota comparison figure; never `total_cost_usd`: that payload is inflated and no divisor corrects it), `servedModel` and attestation; `tools/run_cost.py` prices any record or result the same way. Rating follows `/orchestration_metrics` §Incremental rating.
If a completed review's fold failed, run `sidecar_fanout.py <jobs.json> --out-dir <finished-run> --refold` with its `--fold-*` and `--ledger-*` flags: it dispatches no seat and keeps prior artifacts (tool usage owns attempt paths).

A fan-out is `tools/sidecar_fanout.py`, which detaches every child with `-X` so killing the fan-out's own process stops none of them. Launch it with `--detach` in a foreground call: it validates, hands the sidecar jobs to a detached driver and returns, and the step-6 watcher wakes you. Jobs it placed on the session's own plan are not launched: it prints one `NATIVE` line holding the `Workflow` call (`args.jobsFile` = `<out-dir>/native.args.json`) for you to issue, and with no sidecar job left it starts no driver. The pacing, `maxChildren` and `--max-parallel` rules below bound the sidecar jobs only; the native count is bounded by `orchestration` §5b's one-native-job rule. A job whose named plan has no room, or whose route has no plan with room, is refused in that call, by the dispatch hook from cached capacity and by the planning pass. Every readable plan is paced, so a forecast-only shortfall queues jobs instead of refusing them. Each job end and each launch decision re-reads the plan's capacity. A job launches while every window the plan states holds its drain beside the running jobs. Each window is priced by its own history, because a short window and a weekly one are different units. A plan with nothing running always takes a job, a transport that declares `maxChildren` in the registry (codex: 4) holds that many child CLIs at once, and a caller-set `--max-parallel` bounds the total (default: none). A queued job's line names what held it. Once a job has ended and a window's reading has moved, the observed drain per job replaces that window's forecast for the plan's remaining jobs, scaled by each job's own forecast. A job its plan cannot hold moves to a route sibling that holds it now (a job with a named `plan` never moves), else waits for a running job to end. A plan that reads spent, or whose job ends with a usage limit, moves its unstarted jobs to a route sibling with room, else leaves them `not run` with the reset time. A job with no named `plan` that a usage limit stops mid-run continues on a plan that holds it (`reference/sidecar_runs.md` §Provider usage limit). A job may list every row that meets its bar as `rows: {"<alias>": "<effort>", ...}` in place of `alias` + `effort`; giving both refuses, and each listed row is validated as `alias` is, its tier included. The fan-out applies the ladder's selection line step 2 (`reference/model_ladder_evidence.md`) across those rows' plans and runs the winning plan's cheapest listed row with that row's effort. A move or launch fallback switches alias and effort to the next plan's cheapest listed row. Which rows meet the bar stays your judgment. The admission line names the row (`plan <plan>, row <alias> (<effort>)`) and the run record's `requestedModel` names the row that ran. A job listing one row gets a `spare plan:` line when another plan serving its tier projects unused quota. A window projects none when it has more time left than it has run (its rate was measured over less). A stale or unreadable reading decides nothing, and a queued job still meets its launcher's capacity gate when it starts. A driver held in a backgrounded Bash call ends at the tool's background limit, stranding its queued jobs and its `<label>.md` writes. The alternative is N backgrounded launcher calls, each with its own `-R`, relying on the same default durable files. Capture bytes do not prove a run ended: a retry waits for that run's `EXIT` file, or for its process to be proven gone, and takes a new `-R` path. The fan-out's jobs file may be a `dispatch.js` args file (its docstring owns the job spec). A job's final message writes `<out-dir>/<label>.md` only when a final message exists and the write succeeds. The parent treats an absent required artifact as uncovered. A claims fan-out skips child launcher checks, verifies once with `--root <subject-root>`, and publishes `post_check_claims.json` and `claims.json`; consume `claims.json` after the driver finishes, not the raw spills or event stream. For jobs without claims, consume `<label>.md`. Several jobs run at once receive `dispatch.js`'s single-flight guard as a `-C` file.

A review panel is `sidecar_fanout.py <jobs.json> --review` (jobs from `lens_briefs.py --target sidecar --plan <review_ledger.py plan output>`); its seats wake you once, at the fold's end, with no `wakeWith`, since the fan-out runs the post-check and fold after them. It writes `review.json`: every seat's coverage, source F-ids, exact same-file same-claim M-id groups and quote verdicts. `--review-artifact <review.json> --select <F-or-M-id>` returns the one held finding it names, with its original contributors. Adding `--fold-alias <alias> --fold-effort <effort> --fold-subject <root>::<snapshot manifest>::<file>[,<file>...]` (repeatable) launches one author per subject that received findings, working in the subject's `root`, and follows `commands/agents/review_fold.md` (`--fold <template>` names another brief); `--ledger-stage`, `--ledger-subject` and `--ledger-roster` record the panel. Every `--review` run, folded or not, ends by running `tools/post_check.py review` in-process and writing `post_check.json`, in which `tools/fold_check.py` decides each folded subject. Consumption follows `commands/agents/orchestrator_action_protocol.md` Step 1.5.

## Job kind

A job declares one `kind`: `-G <kind>` on a launcher, `kind` in a jobs file, a Workflow job or a native command. The kind's row in `guards/tool_profiles.json` sets built-ins, MCP servers, disclosure, delegate guard, agent type and tier, and `tools/tool_profiles.py` resolves it. This section holds the choice and no copy of the row's columns.

| kind | fits | litmus |
|---|---|---|
| scout | locate, enumerate, extract | the answer sits in files and needs no project doctrine |
| lens | a survey that must dodge known traps | scout work that needs `MEMORY.md` |
| reviewer | red-team, plan check, verdict lenses | the output is a verdict on a plan or diff |
| author | code or doc authoring, TDD under a spec | the job writes files or runs commands |
| judge | judgment fitting no other row | none of the rows above fits |

The read-only picks carry read-only git (the `git` MCP server: log, show, diff, grep, status, blame, ls-files, rev-parse, merge-base, branch listing, for-each-ref, rev-list), so a history or diff survey needs no shell, and withhold `mcp__ai-worker__write_doc` (`denyTools`); `author` keeps it. A job that runs any other command adds `-t +Bash` (`commands/delegate.md` §Arguments owns the rule). A reviewer that adds it runs as the `lane-review-sh` agent type (`variants`); a native job whose delta has no `variants` entry refuses. A row with `internal: true` serves a harness driver and is never a pick.

Pick the lowest kind the child's work needs, on every model. A bare or pointer child starts at about 21–25K tokens and a full one at about 37K; the child pays that load every turn, it takes window room, and on a row with a long-context price step it can push a request past the step.

Effort follows the ladder cell for the role and work shape. A `see-ladder` row names that home instead of an effort level. Treat an `unmeasured` row as a guess, not a defensible pin. Legal `-e` values come from `model_registry.py effort-values <alias>`: the row's declared values narrowed by the transport's vocabulary, or the transport's values when the row declares none.

**The kind sets disclosure, so size it against the window.** A readable child transcript supplies `turn1ContextTokens`/`turn1ContextPct` in `-R`. Unavailable measurements are null and print no context line. Do not substitute an estimate for an observation. Size the kind against the receiving model's observed first-turn context and usable window; choose `scout` or `lens` unless the work requires full doctrine. Split or narrow inputs when they will not fit. The brief is the bigger lever — hand paths and Grep targets, never the input.

## Optional flags

`-C <file>` extra context (repeatable) · `-a <dir>` extra read grant (e.g. the vault) · `-t <csv>` signed tool delta (§Tool profile) · `-B <csv>` an `arm` job's task built-ins · `-p <mode>` permission mode (default by transport, §Permission mode) · `-P <file>` live progress stream (do not redirect the canonical Bash command; redirection defeats its narrow approval) · `-T <sec>` wall-clock kill (default OFF; the run is killed with exit 124, so pass it only when you can name why) · `-Z <sec>` stall signal on the `-P` stream (set above the longest silence seen on healthy runs of that transport, and pass it when that silence exceeds the default `SIDECAR_STALL_SEC` in `scripts/lib/sidecar_common.sh`; 0 off; a run silent that long appends a `stalled` journal row and keeps running) · `-r <id>` resume a persisted session · `-K <tokens>` the Anthropic child's compaction window, 100000..1000000 (`reference/sidecar_runs.md` §Compaction specifics) · `-M` long context past a row's long-context price step, refused on a row without one; it holds the max window for the whole run, so pass it only to resume (`-r`) a run already past the default window, never on a fresh job (`reference/codex_session_runbook.md` §Launch) · `-W` dispatch inside a peak pricing window on a `gate.peakPolicy: refuse` row. Pass `-W` only when the user explicitly authorized peak pricing in the current conversation; `-A` does not cover it.

`-C` is appended as **SYSTEM instructions**, not a passive data attachment. When a reviewer must judge a plan or rubric as data, label it DATA and blockquote its lines.

### Tool profile

`guards/tool_profiles.json` is the one table (a `kind` maps to its built-ins and its logical MCP servers); `tools/tool_profiles.py` is the one resolver every launcher, `tools/sidecar_fanout.py` and the Workflow hook read. Each launcher passes `--tools`, `--strict-mcp-config` and `--mcp-config` from that resolved profile, and `-R` records it as `toolProfile` (`kind`, `tier` when the kind row names one, `builtins`, `mcpServers`, `add`, `remove`, `overrideMode`, `enforcement: strict`, `mcpRegistrations`); `orchestration_metrics` archives the record's `toolProfile.tier` and `parentSessionId` as the row's role tier and session.

`-t` is a signed delta (`+Bash,-Grep,+mcp:godot`). A Workflow job takes a signed string or list, or a structured `tools.add`/`tools.remove` delta. An unsigned or malformed value refuses rather than losing a requested grant.
Only for `-G arm`, the task row supplies the arm's built-ins. `-B <csv>` carries that row
when a cell also adds a delta: `-G arm -B Read,Glob,Grep -t +mcp:ai-worker` is legal,
while `-G arm -t +mcp:ai-worker` alone is not. An unregistered server, unknown kind,
invalid removal or mixed CSV refuses before spend.

**A dispatch is never granted `Workflow` or `Agent`**: orchestration stays with the calling session. The CLI could grant them, so this is policy: the resolver refuses both in any `-t`, delta or arm task row (`RESERVED_BUILTINS` in `tools/tool_profiles.py`). The one exception is the `bench-score` row, the score daemon's driver, whose whole job is one `Workflow(score_cell.js)` call.

## Permission mode

Provider-transport children launch with `bypassPermissions`: on those seats the auto-mode classifier runs on the provider model through the proxy and denies ordinary scratch and test writes. Under bypass, project hooks (heredoc, kill, harness-edit, gate cadence, dispatch guards) and settings deny rules still decide. Evidence: vault `DevProjects/{{PROJECT_NAME}}/Claude/Meta/Benchmark/harness-guidance-2026-09/permission-mode/`. The anthropic transport keeps `auto`. Pass `-p` only to override a default for a stated reason; never pass it to retry an action a hook or a deny rule refused.

Every child also gets the **autonomy rail** (`sidecar_common.sh` `sc_build_disclosure`, all tiers, all models): it runs unattended, never ends on a question, decides and states the assumption, reports a blocker inside the deliverable. At consumption, the parent rates a question-only final message as no delivery.

Never: `-n` (a turn cap discards a paid run) · an unverified `CCP_BIN` override (`environment_bootstrap` owns the machine detail) · a pin from ANOTHER transport's vocabulary inside Workflow `agent()` — role names on a provider session, vendor ids on an Anthropic one. Pin the session transport's own ids; `hooks/workflow_provider_guard.py` denies the other and names the roster.

## After launch

`reference/sidecar_runs.md` owns what happens once a run starts: resume, provider usage limits, compaction internals, detached-run wakes and exit codes. Read it when a run ends, refuses, stalls or wakes you. Its rules that shape the brief at launch:

- Pass the brief path absolute and native: the re-prompt hook opens it from the child's cwd, which is a worktree or a temp dir.
- A job whose `-d` is a linked worktree cannot Write, Edit or NotebookEdit into the main checkout: `hooks/sidecar_workdir_guard.py` denies it, except under the job's spill dir (the directory of its `-R` record) and the paths its brief's `task` block `writeSet` names. Declare every main-checkout path the job writes in that `writeSet`, and put its report under the spill dir. A Bash command with a clear write there (a redirect, `tee`, a `cp`/`mv`/`install` destination, `sed -i`, a mutating `git -C <main>`, a python path literal beside a write call) is denied the same way; a target it cannot resolve statically is allowed.
- Name the brief's on-disk outputs and ask for partial output early: that is the resume path.
