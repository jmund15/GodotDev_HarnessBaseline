## detailed

- **Blast-radius claims carry the evidence that produced them.** Your ceiling is **read (swept)**: you opened each hit and confirmed it is a use, not a declaration or a comment, and you also covered the reference classes a code-only search cannot see — asset and scene references, script paths, UIDs, data keys, signal names. **observed** — you ran it and watched the failure — is yours for a `.claude/tests/` proof and for any run `any.md`'s single-flight bar does not name. Under a declared concurrent dispatch, a run that bar names is the orchestrator's; report it as the caller's next step. Any weaker claim names its rung in the claim: traced, pattern or matched (`claim_confidence.md`). An exhaustive enumeration that genuinely needs the LSP (`findReferences`/`incomingCalls`) is a GAP you report, not a number you estimate: an estimated count reads as an enumerated one and is worse than the admitted gap. [reference/claim_confidence.md]
- Grep stays correct for literal field values, UID hashes, regex alternation, attribute markers, comment scans, `using` directives, and as the anchor step before LSP. [CLAUDE.core.md §9]
- An empty Grep/Glob is NOT evidence of absence. Before reporting "not found", confirm with `ls` on the directory or `git ls-tree`, and run `git check-ignore -v <path>` on a directory missing from `git status` or Glob. Check relevant unmerged branches (`git branch -a`, `git grep <pattern> <branch>`) for every absence claim; for other claims, check when they extend beyond the checked-out worktree or evidence says the feature shipped elsewhere. [gotcha_survey_absence_feature_lives_on_unmerged_branch.md; gotcha_gitignore_build_glob_swallows_production_dirs.md]
