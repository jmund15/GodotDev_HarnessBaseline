# /ladder_ingest — model comparison → ladder evidence

The paired-ARM sibling of `/pin_ab`. An **arm** is one model's run of the shared prompt, however it was dispatched:

| arm | operand |
|---|---|
| a Claude Code session | `<id-prefix>` — from `session_digest.py --list 12` |
| a workflow or Agent-tool subagent | `<path>.jsonl` — a sibling `.meta.json` supplies model + label |
| a sidecar dispatch | `<path>.record.json` — deliverable read from the sibling `.out.json` |
| a whole workflow run | `<dir>/` — expands to every `agent-*.jsonl` in it |

Operands mix freely. `--out` is always required. With no arm the tool prints its usage — run `session_digest.py --list 12` for session ids, or point at a workflow run dir. One arm writes the files and says nothing is comparable.

**Precondition — the arms read a frozen input** (`orchestration` §0). Repo moved mid-run ⇒ ingest nothing, and say so in `doesNotShow`: this is not recoverable here.

1. `python3 .claude/tools/ladder_ingest.py <arms...> --out <vault>/Claude/Meta/Benchmark/ladder-ingest --slug <slug>` → per-arm files + `COMPARISON.md`. Read its `same_prompt` and `prompt_not_recorded` lines first: arms that ran different prompts are a weaker comparison, and the file says so rather than hiding it.
2. Resolve the executor-role judge and its effort from `reference/model_ladder_evidence.md`; `model_registry.py for-role executor` only locates the rows. Then dispatch `judge_brief.md` + `judge_schema.json` through `/delegate` with `shape: review` and `schemaFile` set to `judge_schema.json`, currency stated.
3. `ladder_ingest.py --apply <judge-result.json> ...` → Adjudication section, prints `ladderClause` + `orchestrationNote`.
4. `/codify` the clause onto the ladder row, then run `python3 .claude/tools/ladder_prose_check.py` — it must exit 0.

## Board sweep: the battery reaches the ladder by task

A cheapest-reliable or strongest-pick verdict is relative, so one row's new cell can change the verdict of every row claiming that shape's tier: sweep by task, never by row. `bench.py ladder-lag` lists each task whose ranked board cells changed since its last sweep (new, re-judged or voided); `bench.py doctor` and the session banner show the same list. Closing a campaign sweeps the tasks it scored (`benchmark_design` §11).

1. Write `model_registry.py for-role <tier>` for each tier the tasks measure to one scratch file. Dispatch one read-only `survey` job per group of tasks sharing a work shape, briefed with [`reference/ladder_board_sweep.md`](reference/ladder_board_sweep.md) plus its tasks, the tier file and the vault battery folder.
2. Reconcile each gap with the other sources (§What lands), apply what lands, run `ladder_prose_check.py`, and update the registry fields the results change (roles, supplementary, effort evidence, compaction notes).
3. Read each swept model's rescue rate from `board.json` `rescueRates[<model label>]` (`cells`, `rescued`, `byKind`; a rescue is the launcher's resume on an empty final turn or a schema failure). When `rescued` over `cells` marks a reliability limit in agentic use, the `±` cell names that limit in words ("needs a resume on empty turns in agentic work"); the count stays out of `±`. No `rescueRates` entry means unmeasured, not clean.
4. Run `bench.py ladder-lag --mark <tasks>` and commit the ledger with the ladder edit.

## What lands on the ladder

A cell states whatever decides a pin within the tiers the row claims, for example the work it is the cheapest reliable pick for, the work where it is the strongest pick when quality outranks cost, a strength, an efficiency or inefficiency, a weakness or a reliability limit. A `−` clause never bars a work shape inside a tier the row claims: a row that cannot do a tier's work loses the registry claim instead. It never states a benchmark placement or figure: a `bench` result reaches a cell only where it disagrees with `pub` or `use`, or shows a failure a pin must avoid. When sources disagree on a shape, first find the scope that separates them (problem size, how open the problem is, how many parts interlock) and state each verdict with its scope ("matches opus on scoped architecting; opus is stronger on complex open design"). With no separating scope, the owner's `use` ruling stands; between other sources (`bench`, `pub`, an `/eval_dashboard` readout of rated dispatches), weigh how many runs back each side and how close each is to the work the pin serves. A thin side (no repeat behind it, or a gap inside the run-to-run spread) changes no clause the other side supports: queue a repeat run or a `/pin_ab`.

Lead a cell with its routing verdict ("the cheapest reliable execution of a converged plan", never "executes a converged plan at the top of the board"). A row's `effort` and `±` cells cover every work shape of every tier its registry rows claim, including everyday shapes no battery task measures (surveys, explore lenses, rubric checks). A measured shape gets its verdict judged against the other rows claiming its tier (`TASKS.md` maps tasks to shapes). An unmeasured shape takes its verdict and starting effort from the row's nearest measured shape, its intel and the owner's rulings, and is marked unmeasured. A row that matches a pricier row on a shape is that shape's cheapest reliable pick, and the cell says so even when the row's other results are unremarkable. A clause about a seat or a pairing states when an orchestrator adds the row and what to check in its return, never only that it does less. A strength claim needs a lead outside the judge band; a cheap row that matches the strongest rows says so, since then no pricier pin buys quality. A comparison may name another row's family ("trails opus on open design"); `tools/ladder_prose_check.py` fails a name no ladder row covers.

- **Write a model tendency, never this run:** *"exhaustive over a diff, slow"*, not *"this run found N defects"*. Word an observed outcome by how many runs show it: *can* for one or a few, *often* or *usually* as they recur, *almost always* only across many; never as a certainty (*"its findings are wrong"*). A routing directive conditioned on the work (*"never the lone seat on a broad review"*) is policy and stays absolute. Registry `supplementary` marks a tier a row fills only as an added review seat beside a qualified seat; ingest sets it only when the owner rules it, and a cell states the tendency without restating the entry.
- **`effort` owns every effort level; a `±` cell names none.** A `±` cell compares with another row by family and scope ("trails opus on complex open design"), never by that row's effort, and never says which effort to pin.
- **An `effort` cell gives the starting effort per work shape: each level, then the shapes that start there, levels separated by `·`.** It adds the signal that moves an effort (how well a defect can hide, how convoluted the problem) only where that signal changes a pick; `orchestration` §5 *Effort* owns the raise and the lower. A range names both its ends. A shape whose breadth and depth vary from job to job (surveys, explore lenses, chained research) takes a range from the lowest effort measured or used to serve it up to the row's top allowed effort, higher as the breadth and depth the question needs grow.
- **A clause is as wide as the evidence behind it.** A result from one task, one effort or runs whose spreads overlap supports a scoped statement ("showed no gain on chained research; untested elsewhere"), never a claim about the model or the effort in general. An effort that is enough on one task has not shown the others fail, and "only", "always" and "never" need results across shapes.
- **An effort level earns a place only where it can be the pick, and the owner accepts any removal.** The battery command `ladder-dominance "<model>·<effort>"` lists, per task, the pins that score within the judge band or higher at no more cost, with the speed gap, each pin's rated real dispatches and whether it is paid from the same plan. Propose removing an effort level only when same-plan pins dominate it on every shape its cell claims for it. A dominator on another plan leaves the level as that plan's fallback when its quota runs out; dominance on a shape the cell does not claim says nothing about the level; an unmeasured shape gives no verdict. A dominator counts only if it is available and claims the shape's tier. The proposal carries the listing and what the real dispatches add: they corroborate it, or show the dominator never ran here or ran poorly. The cell changes after the owner accepts, and a level whose cell states what it buys is not proposed again. Registry `effort.avoid` lists only a level removed this way.
- **A cell is read mid-dispatch, so every clause changes a pick.** Cut a clause that restates another column, the Role definitions or the selection rules, explains a term, or narrates why. Call an effort level an effort, never a rung.
- **Every shape term in a cell names work an orchestrator can recognize before it dispatches, and is defined in the ladder's Role definitions or written as a plain description.** An orchestrator reads the ladder cold to pick a row for work in front of it; a property it cannot see at that moment (a brief whose premise is secretly false, a benchmark's scoring partition) is a benchmark construct, never a shape, and a term defined only in a benchmark file is undefined.
- **Rewrite an existing clause or add none.** Appending one observation per ingest turns a routing table into a changelog.
- No score, task id, date, arm count, wall-clock figure, multiplier, run description or per-run link in `±` or `effort`; `ladder_prose_check.py` enforces this mechanical half.
- An observation that would not recur belongs nowhere. Say so in `doesNotShow` and stop.
- **Authority:** the owner may edit any cell at any time, and that cell stands until the owner revises it. An agent proposes a change with its evidence through this command. Any source mix can set a row, and a row and its tier claims may start on `pub` evidence. Tag the row's `evidence` cell with every source it rests on; the claim itself goes to `Claude/Meta/Benchmark/ladder-ingest/pub-evidence.md` (a `pub` claim) or the board (a `bench` cell), never into a cell.
- Set `cost` from tokens per result (output, uncached input and cache reads counted apart; a cache read costs about a tenth of an input token) times the row's per-token price (registry `price`); never from turns × minutes.
- Rows name product-line families, never versions or transports. Parallel active variants with distinct use (a Max line beside a Flash line) are separate families. A family with a fanout-or-above claim gets its own row; scout-only families share the `scout pool` row, which lists them. A new version takes over its family's row: replace only the cells it ran, and keep older evidence for the rest until a cell or an owner ruling shows the new version differs. A version gets its own row only when two versions are worth running for different work.
- **Version takeover audits every inherited clause.** When a row's model version changes, read each `±` and `effort` clause against the new version's current board cells, the owner's rulings and what the new version's published results say. A clause stays when one of them backs it or none contradicts it; a contradicted clause is rewritten or deleted. Then run the battery command `ladder-lag --audited <row>`: the session banner names each row whose version moved since its last audit, so inherited clauses cannot outlive the version they were measured on.
- Tier claims live only in registry `roles`, never in a ladder cell; a `supplementary` entry is a seat constraint, never a claim, and lives only in the registry. No row claims another model's alias.
- A cell that contradicts an effort level goes to the owner before the level changes.
- The ladder holds only what a reader pinning a model needs. An editing rule lands here, and `ladder_prose_check.py` `TOP_LEVEL_BANNED` names its phrase so it cannot drift back.

Done: Adjudication present, the ladder row reads as a tendency, `ladder_prose_check.py` exits 0, verdict in `orchestration_verdicts.json`.
