# /part_drive — Part Drive (Brief → Plan → [Approve] → Execute → Ship)

**Invocation:** `/part_drive <part-name> [roadmap-path] [--plan-only]`

Drives a `plan-pending` Part from its design surface to shipped code in one autonomous session.

`--plan-only` stops at an **approval-ready plan** and hands off — use it when the user wants to review the plan before any code is written. Without the flag, the drive runs brief-through-commit and never stops for plan approval.

Resolves the Part on the nearest-ancestor `roadmap.md` (same convention as `/plan_part`).

Use [`/part_execute`](part_execute.md) when an approved plan file already exists. Use [`/feature_drive`](feature_drive.md) when the work is not a roadmap Part and the design was resolved in conversation. The unflagged form is for Parts the user trusts end-to-end — typically retirement/refactor Parts with a tight design surface, or Parts whose design doc already resolved the taste questions.

**Session effort — set by residual design ambiguity, not by stage.** A `plan-pending` Part with a decided design plans at `medium` and reaches ceiling there. Reserve `xhigh` for design-thin, premise-unverified, or drift-flagged Parts — it buys buried-fork discovery no lower effort finds. Discovered residual ambiguity is a kick-back signal (halt (a) / arch gap), never grounds for an effort raise.

## What the flag changes

Everything else is identical. These four differences all follow from one fact: **`--plan-only` has an approval presentation, and the unflagged form does not.**

| | `--plan-only` | unflagged (through-ship) |
|---|---|---|
| **Steps run** | 1–3, then *Present for approval* | 1–7 |
| **Load-bearing taste fork** | Batch every fork into ONE `AskUserQuestion` (max 4; chain if more) BEFORE presenting, and write the picks in as fact — the approved plan carries zero open user-decisions | **halt (f) immediately.** No batching point exists, and reversibility drops at the implementation boundary |
| **Write surface** | The plan file + `/explore`'s scratchpad files ONLY. No production code, no tests, no roadmap edits — those belong to `/plan_handoff` | Steps 4–7 write freely per the plan |
| **Close-out** | Offer [`/plan_handoff <plan-file>`](plan_handoff.md) with the plan path only. Offer, never auto-chain | `/update_roadmap` Part → `complete`, then offer `/pr_ready` |

**Plan Mode is retired from this and every planning path** (`feedback_plan_mode_retired_from_planning_flow`). Under `--plan-only` the *Write surface* row above is therefore a rule you honor, not a wall that stops you — nothing enforces it at the tool layer, which is exactly why it is stated. An edit outside those paths during the plan phase is a defect, not a shortcut.

## Halt valves

| Valve | Trigger |
|---|---|
| **(a) Factual-basis drift** | `/plan_part` macro drift; a plan-referenced file/type missing at execution; an agent's load-bearing empirical claim failing first-party verification — one that *confirms* the plan is fine; one that contradicts it halts |
| **(b) Unbounded scope** | File list can't be bounded at plan time, or execution discovers the Part is materially larger than planned |
| **(c) Prior-art conflict / subjective gameplay** | `exp-prior-art` finds an existing 2+ family the plan would parallel → halt *before* drafting. At execution: behavior that can't be test-gated — implement mechanism, flag for playtest, continue; halt only if the Part's DoD *is* the subjective behavior |
| **(d) Gate / audit failure** | Regression-gate failure beyond trivial in-scope fix; unaccounted baseline drop; a `/plan_check` agent INCONCLUSIVE or uncorroborated twice (after the one re-run) |
| **(e) Critical not converging** | Criticals persist after 2 revise rounds, OR a revision introduces a new critical (divergence). Halt with the plan at its last-revised state + the full critique trail + a recommendation: address them manually, or run `/architecture_brainstorm_redteam` if they indicate an architectural dead-end |
| **(f) Load-bearing taste fork** | Appetite-dependent question whose answer changes the plan's *shape*. Routed per the flag table |
| **(g) Architecture non-convergence** | A `critical` finding from the shape's structural lenses — `plc-architecture-quality`/`plc-pattern-fit` on a code plan, `plc-doctrine-consistency`/`plc-instruction-quality` on a meta one — that fails revise-and-reconverge (disputed on evidence, or resolves to a taste fork) — annotating a disposition and proceeding is never the exit |

## Dispatch topology receipt

Before every dispatch stage, compose `orchestration` §0, §5, and §11 into one **Dispatch Topology Receipt**. Its pre-dispatch half names independent outputs, risks, fixed seats, contained-job deduplication, width, role floor, effort, and currency. Its post-journal/PINS half compares actual rows, pins, and coverage with that receipt. This call site adds no role or model table.

## The flow

1. **Brief** — run [`/plan_part <part>`](plan_part.md)'s briefing procedure; its HARD-STOPs and State gates bind. **Not `plan-pending`, unresolved name, or unresolved redirect → the drive ends here:** surface the redirect and stop. This abort fires *before* the loop, so it is not one of the halt valves. part_drive adds: **verbatim** design-surface loads (section-bounded reads), codebase verification, and drift classification. **Macro drift → halt (a).** The design section assigns THIS Part's items; the roadmap's sibling rows + the design's Parts-decomposition section are the boundary authority for what prior Parts shipped or later Parts defer. Read the roadmap by grep: the Part row, its sibling rows, and the *Currently ready* section carry the boundary signal; the Mermaid block + classDefs are pure table redundancy — never load them.
2. **Explore, then plan in-session** — dispatch [`/explore`](explore.md) with the Part as `TOPIC` **before any drafting**. Do not re-search memory by hand — `exp-memory` is the floor lens and covers `.claude/auto-memory` + the unconditional `arch_rule_*` sweep; the trigger-gated lenses cover the dimensions a hand-rolled pass missed.
   - **Copy the dossier's `constraint` claims into the plan file** under a `Constraints` heading, **with their evidence quotes** — `/plan_check`'s memory lens then verifies against cited evidence instead of re-deriving it. `N/A — <reason>` is acceptable; silence is not (the plan-file-write hook nudges only — this is yours).
   - **Absorb every `premise-contradiction` claim and close every UNCOVERED dimension BEFORE drafting.** A premise corrected after the plan exists costs a rewrite; an uncovered dimension means the exploration is not done — close it, don't draft around it.
   - **An `exp-prior-art` claim naming an existing 2+ family the plan should extend rather than parallel → halt (c) before drafting** (`feedback_inspect_existing_abstractions_first`).
   - **Depth does not narrow exploration coverage.** `/explore` owns its no-op rule and trigger table; retain both floor lenses and every triggered lens.
   - **Validate** every tentative design decision against the codebase — override the brief where the code disagrees — and **read the critical files first-party** before committing to them.
   **Draft authorship is session-model-relative:** in a multi-Part chain (e.g. `/design_drive` through-implementation), **or** whenever the session model sits above the architect tier on the ladder (`reference/model_ladder_evidence.md` §Role guidance), **dispatch the plan DRAFT to an architect-tier arm** — `architect·medium` on a thick design surface, via `dispatch.js` with a pointer brief (design-section anchors, the `/explore` dossier path, memory constraints, plan-file-format; the arm reads sources in its own context). Why: over a chain, driving-session context is the binding constraint, and drafting's dominant failure mode is grounding diligence. A standalone Part on an architect-tier session authors inline — dispatching your own tier is round-trip overhead with no intel gain (at matched effort; at elevated session effort, dispatch the converged chunk at a low-effort pin — own tier included — and keep blocking runs + review in-session). A THIN design surface is never grounds for a stronger author or an effort raise — it is halt (a)/arch-gap (a Part needing design decisions at plan time isn't plan-pending). Post-`/plan_check` folds may continue on the same arm via `SendMessage`; the driving session always keeps the brief, first-party verification of refuting claims, fold adjudication, and the convergence verdict. Pass `agentType: "general-purpose"` with the resolved `model` and `effort`.
   Prior art is already established in the dossier — do not re-run it. Resolve the remaining analytical questions from code (never guesses). **Land the plan file** at `.claude/plans/<slug>.md` with the `**Roadmap:** <path> — Part **<ID>**` header (drives `/session_end` drift detection) and the three architecture-bearing sections per [*Plan-file format*](../skills/_brainstorm_shared/plan_file_format.md): **Families** (axis statement per new rung/variant), **Authored surfaces** (home + consumer + failure mode per new export/node/key), **Designer surface** (what an author sees; hand-configured vs automatic). Empty-with-reason is valid; absence is a plan_check critical. **File list cannot be bounded** ("…and possibly others") → **halt (b)**. The plan file is mandatory in both modes: the `/plan_check` audit surface, the deletion parity ledger, and the Decision-record home. Include the *Closing steps (Definition of Done)* section (per *Plan-file format*): gate → commits (submodule order) → `/update_roadmap` flip.
3. **Audit & converge** — run [`/plan_check @<plan-file>`](plan_check.md) with the full plan in shared CONTEXT (lenses read that context, not the plan again). Lens coverage is set by plan shape; seat width by `orchestration` §2 and `/plan_check`'s seat map. A harness/doctrine plan swaps the C#-calibrated lenses for the meta set (`/plan_check` Phase 1a decides the shape — pass `--code`/`--meta` to override). Fold findings per *Convergence* below; write the plan per [*Plan-file format*](../skills/_brainstorm_shared/plan_file_format.md) — resolved design as fact, *why* inline, no process-meta or open-decision sections.
4. **Execute** *(skipped under `--plan-only`)* — the converged plan is a landing spec. Route execution per `orchestration` §11 (session-model-relative dispatch — no tier logic here); dispatch shape is free per that same skill — one executor, parallel executors over independent slices, or a Workflow pipeline (**this step IS the Workflow opt-in authorization**). Before the first dispatch, map slices to jobs per `orchestration` §11 *Slices are commit units*. Whoever drives keeps spec OWNERSHIP (the brief, fold adjudication, final plan content — the draft itself may be delegated per step 2), diff review, gate adjudication, and commits at the driving session regardless of fan-out.
   - **Dispatch is non-blocking** — while an executor runs, spec the next slice and review the previous slice's diff; only slices whose seams the plan already fixed may be specced ahead. Consecutive slices on one subsystem continue on the same executor arm via `SendMessage`; a new arm is for a new subsystem or a rejected slice.
   - **Take the `/part_execute` stance:** TDD per slice (strict in Logic; RED proven before GREEN for any behavior change — a one-line wiring change still gets its RED), deterministic-Gameplay via ISceneRunner, subjective flagged for playtest (**halt (c)**).
   - **Slice verification is a targeted `-Filter` run over that slice's blast zone — never the full gate.** The full gate is step 5, once. **Batch the commits to step 5** so one green run backs them all. Cadence doctrine + the long-drive checkpoint exception: `change_control` §Gate cadence.
   - **Retirement/refactor Parts — transient parity capture first:** stand up a self-baselining scratch test against the CURRENT code (write fixed-seed golden outputs if absent, else compare). It is the empirical half of `feedback_refactor_parity_audit` and the only instrument that catches silent drift when the old oracles are themselves being deleted. Post-deletion: retired-name grep sweep including doc comments (`gotcha_errorsonly_build_hides_cref_drift`).
   - **A check written to diagnose, not to gate, is removed before the slice closes** unless the plan's test intent names it. Scratch parity harnesses and scaffolding probes are diagnostic; a suite the plan named is not.
   - **Edit strategy:** Edit surgically; rewrite a whole file only when the change touches most of it. Run any file-wide regex pass before targeted `Edit`s on the same file — a regex pass invalidates `Edit`'s read state.
   - **Diff review is a gate, not a glance.** Each delegated slice's diff gets a recorded verdict in the plan file's Decision record against four rubric axes: composition-vs-inheritance, authored-surface coherence (new exports vs `rules/design_litmus.md`), existing-family reuse, designer ergonomics. **REJECT** re-dispatches the slice with the violation named.
   - **Close-out design review** — one design-review pass over the FULL working diff: dispatch one architect-tier agent via `dispatch.js` (`architect·medium`; mandate: the same four axes + `checklists/code_quality.md` Design items). Every finding is explicitly dispositioned — fix now / worklog with reason / refuse with evidence — in the final report. Not auto-blocking; **undispositioned findings are**. **SKIP the dispatched pass** when ALL hold: (a) pure refactor/parity-gated Part with zero new authored surfaces (no new consumer-facing types, exports, scene nodes, or Jmodot code), (b) `/plan_check` ran with the architecture lenses, (c) the orchestrator's inline per-slice diff review is clean. Record the skip + basis in the final report (inline review + parity gate + downstream `/session_audit` carry coverage). Parts that author new surfaces always run it.
5. **Verify** *(skipped under `--plan-only`)* — **by chain position** (`change_control` §Gate cadence): a mid-chain Part runs **the project's scoped verifier over its accumulated blast zone** and neither gates nor commits; the chain-final Part of a multi-Part drive (or a standalone Part with no chain) runs the project's FULL, single-flight regression gate marked `# gate: final` (§Gate cadence names both), which backs every commit in the drive. Failure that isn't a trivial in-scope fix → **halt (d)**. A trivial in-scope fix re-verifies at the fix's blast-radius width — never a reflex full re-run (`change_control` §Gate cadence). A baseline *drop* that is exactly accounted by the Part's test arithmetic (N retired + M added) may be applied with prominent disclosure in the report + commit message; any unaccounted drop → **halt (d)**.
6. **Commits** *(skipped under `--plan-only`)* — categorical split, submodule first per the project's submodule discipline in `change_control` (verify the submodule's `origin` default branch contains the commit, message via temp-file `-F`, pointer bump shows `160000`). **Concurrent-session index hygiene:** enumerate `git status --short`; treat any staged entry you didn't stage as foreign — preserve it and coordinate an isolated commit before staging your own work; verify the final index and committed file list. A foreign staged entry silently rides into `git commit` even without `-a`. Foreign worktree WIP (modified/untracked files from a parallel session) is never swept in. Do not push.
7. **Close out** — per the flag table. Unflagged: [`/update_roadmap`](update_roadmap.md) Part → `complete` (applied directly under the one-shot directive; diff surfaced in the final report), then offer `/pr_ready` if the Part rides toward a PR. Under `--plan-only`: **present the plan for approval** — FIRST confirm it satisfies *Plan-file format*, THEN present it **with the process narrative in the message, not the plan** (what `/plan_part` drifted, what `/explore` contradicted, what `/plan_check` flagged each round and how it resolved, the convergence basis), name the plan file path, and stop for the user's word. On approval, offer `/plan_handoff`.

**Context checkpointing** applies throughout — the contract is `orchestration` SKILL §10.

## The appetite invariant (the core safety rule)

**[Shared]** The full rule — lexical tripwire, always-taste set, errs-toward-taste default — lives in [`_brainstorm_shared/appetite_invariant.md`](../skills/_brainstorm_shared/appetite_invariant.md). It is the load-bearing safety rule of this loop.

A question is **TASTE** — never resolved by guessing to reach convergence — when its answer depends on an unstated **appetite** (how much coupling, future-proofing, scope, performance margin, risk, or feel is acceptable), *even if phrased analytically*. An **analytical** question has a single correct answer *given a stated appetite*.

## Convergence

- **The convergence target counts RIGOR-HOLES only** — critical, addressable findings. Loop step 3 until **zero critical rigor-holes** remain.
- **Auto-apply is intent-preserving ONLY.** Auto-apply a revision only when it cannot change design intent — adding a named failing test the plan already implies, fixing a stale file ref, correcting a namespace/path, formatting. **ANY** revision that changes a type / signature / default / export name-or-shape / scope, or merges/splits a design element, is taste-adjacent → route per the flag table, never auto-apply. When unsure whether a revision preserves intent, do not auto-apply.
- **Round cap = 2.** Distinguish a **persistent** critical (survives a revision) from a **new** critical (a revision introduced it). A *new* critical in round 2 means the loop is **diverging** → halt (e) immediately; don't spend the "last" round. Persistent criticals after 2 rounds → halt (e). **Tie-breaker:** when a round-2 critical's identity is ambiguous (reworded but addressing the same rigor-hole), treat it as **persistent** — err toward the halt, mirroring the appetite invariant's conservatism.
- **Round-2 re-dispatch is conditional.** If every folded revision was itself derived from a first-party code read (you verified the mechanism in source before the plan text changed), the round-2 re-audit re-verifies facts that already have primary evidence — skip the dispatch and record the basis in the Decision record. Re-dispatch only for revisions resting on agent testimony or untested inference, as ONE focused fresh verifier — an independent dispatch, never the original agent — under `/plan_check`'s evidence-quoting rule.
- **Liveness precondition (closes the false-absence path).** "Zero critical rigor-holes" counts only when each `/plan_check` agent **corroborated** its clean result — echoed *what it examined* (symbol-refs / memory-hits count, abstractions checked). An agent returning "0 critical" with no liveness signal is the `gotcha_workflow_fanout_search_false_absence` class — a silent read-failure reads identical to a genuine clean → route to halt (d), never count it as convergence.
- **Refuting empirical claims are verified first-party before they count.** An agent that *refutes* the plan's factual basis ("already implemented / file missing / already refactored") must quote raw tool output, and you Grep/Read at least one quote directly — verification agents fabricate confident file-state reads. A fabricated refutation is discarded and recorded; never re-dispatch the same agent, and never spend a convergence round on it.
- **`/plan_check` SKIP substitution.** On a legitimate SKIP (≤2 files / no new types / no deletions) no audit runs, so "zero criticals" is vacuously true. Convergence then REQUIRES step 2's validation pass plus the `/explore` dossier (the validated decision list and the claims are the artifacts), and — under `--plan-only` — the approval presentation MUST disclose *"plan_check SKIPPED (sub-litmus); convergence basis = step-2 validation + explore dossier."* A SKIP never satisfies convergence on its own.

## Autonomy discipline

- **Don't re-ask mid-stream.** Once invoked, run to a halt valve, to the approval presentation (`--plan-only`), or to close-out; don't ask "continue?" (`feedback_honor_execution_directive`).
- **Resolve analytical plan questions at plan-time** (`feedback_resolve_questions_in_plan_not_execution`).
- **Don't compress step 2 because the brief is rich** (`feedback_dont_compress_socratic_on_rich_prompt`). The `/plan_part` brief is starter material; `/explore` and the validation pass are not redundant with it and are not optional.
- **No worklog adds during the plan phase.** Deferrals surfaced then go into the plan's Decision record or the taste batch, not the worklog (a post-approval action).
- **Context-exhaustion is a split signal, not a valve.** A Part large enough to exhaust context mid-convergence should have been split at arch Step 5 or caught by valve (b). If it can't fit, halt and split the Part — never truncate a half-converged plan.

## Anti-patterns

| Rationalization | Reality |
|---|---|
| "It's a deletion Part — nothing to TDD." | The retirement's behavior changes (collapsed loops, pref flips) still get RED→GREEN, and the parity capture pins everything that must NOT change. |
| "This taste question is small — pick the sensible default to keep the drive moving." | The flag decides where taste GOES, never whether it is honored. Batch it or halt on it. |
| "Criticals remain but I'm out of rounds — present the plan anyway." | Approval-ready and known-critical are mutually exclusive. Halt (e); never present a known-critical plan for approval. |
| "The user wants a plan review, so I'll use a separate command." | There isn't one. `--plan-only` IS that path. |
