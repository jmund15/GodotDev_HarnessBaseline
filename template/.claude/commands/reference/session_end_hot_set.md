# Phase 3.7: Hot-set review

Gate: `--only hot_set_review`; a true value lists each over-baseline budget in its `basis.rows`. Before the review run `git status --short -- <those rows' files>`: a file dirty then and absent from the Phase 0 digest's `files_modified_counts` is peer-dirty, and this session's own edits never count. Run the session-audit command with `--hot-set .claude/scratch/session_end/<sid>/predicate_hot_set_review.json`, rule its `held` ids and failed checks per Step 1.5 under Phase 1's disposition rule, then re-measure with `python3 .claude/tools/load_census.py --budgets`. Set a tripwire's baseline to its new measurement by writing `[null, N]` in the project's `tools/load_census.project.json` `budgets` (a fork that has not moved its tripwires out yet writes `(None, N)` in its own `tools/load_census.py` `BUDGETS`), only when all three hold:

1. a returned review: a blocked or partial one sets no baseline;
2. every FIX on that budget's files is dispositioned (applied, or rejected with a reason), and every addition since its `baselineCommit` holds a FIX disposition or a `kept:` line (`baselineCommit` is the last commit that recorded the baseline wherever the merged budgets took it from: the project profile's literal when the profile supplies the budget, else the `BUDGETS` literal; no recorded commit reads the whole budget);
3. no file the budget measures was peer-dirty when Phase 3.7 began.

A project that records no tripwire baseline gets no tripwire row: the key is absent from the merged budgets, so `over_baseline` names nothing for it and `--budgets` prints no tripwire line for that measurement. An `oversized_body` row's re-base writes the body's measured bytes into the project file's `known_oversized_no_selector` under the same conditions. For that row, condition 2 reads `baselineCommit` as the commit that last recorded those bytes, or the whole body when none has. Otherwise every baseline stays and the predicate stays true for the next close. A peer-dirty measured file defers that budget's re-base to the next close with none, and its FIXes stage only this session's hunks. The close report shows each budget's delta, each `kept:` line and each deferred re-base with its reason. A blocked review never blocks the close.
